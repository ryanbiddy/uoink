## Cancellation before launch

The diagnostic paused the original caller after Mirror stored its prepared
session and before the original `launch` entered Popen. Cancellation reported
death, removed Mirror/global retention and released the gate. Resuming the
original caller then started launcher PID 70036 and writer PID 62724. The
writer was physically alive, admission was cancelled, no owner remained held,
and no lease or content-mutation command had been sent.

This is an untracked idle child, not evidence of post-timeout publication.
Cleanup through the original retained test reference confirmed termination.
Launch must refuse a previously cancelled session or retain ownership across
an actual launch in progress until that outcome and child death are resolved.
Cancellation cannot treat an unresolved Popen handoff as proven death.

## Foreign local-helper adoption

The originating thread started a Mirror session. A different thread had no
session or exclusion context but called the same Mirror object's local intent
helper. The new fallback selected `self._vault_io` solely because it was live.
The put case replaced `{"owner":"original"}` with `{"owner":"foreign"}`
through writer PID 57928. The unlink case deleted the original intent through
writer PID 5900. Both helpers returned success, and both original writers were
still alive. Cleanup confirmed termination in each case.

These are actual disposable local mutations at the helper boundary named in
B6's brief. They do not establish that a normal public resync bypasses its
outer lock. Helper reuse needs the original operation's context or an explicit
originating-helper binding; a shared Mirror object alone is insufficient.
Keep the existing same-thread helper controls and stale-session refusal.
