Proof receipt schema v2 retains the legacy envelope and derived item views and
adds the following required fields. Schema v1 is accepted only for mock regression
fixtures. It can never establish measured proof. The validator never upgrades old
receipts or reconstructs missing original process output.

| Field | Producer contract |
|---|---|
| `calls[]` | One immutable record per actual CLI process: unique `call_id`, ordered `attempt_ids`, exact `argv`, `schema_text` and `schema_sha256`, `stdin`, `stdout`, `stderr`, `start_monotonic_ns`, `end_monotonic_ns`, `exit_status`, `timed_out`, `cancellation`, raw `usage`, raw `modelUsage`, and `cli_estimated_cost_usd` |
| Artifact reference | `{path, sha256, bytes}` relative to the receipt directory, using forward slashes; alternatively `{base64, sha256, bytes}` for exact inline bytes. Hash-only unavailable artifacts fail validation. No historical absolute path is opened. |
| Attempt additions | `call_id`, `model_result`, `claim_event_id`, `submit_event_ids`. `model_result` is the unique original row or null for missing/duplicate/unparseable rows. `result` is the actual submitted result, which may be a generated error. Existing text/byte fields are derived item views, never process totals. Item `usage` and estimates are unavailable; report them once per call. |
| `completion_order[]` | One `{attempt_id, completed_monotonic_ns}` per attempt in actual coordinator completion order, including interleaved batches |
| Target addition | `terminal_service_state`, separate from the last reasoning disposition; a cancelled third claim remains visible |
| Transport additions | `http_event_id` or null for reasoning failures, and `occurred_monotonic_ns`; preserve distinct linked events |
| `totals` | `model_calls = len(calls)`, `item_attempts = len(attempts)`. `prompt_bytes` is exact stdin bytes, `response_bytes` exact stdout bytes, `stderr_bytes` exact stderr bytes, `schema_bytes` exact UTF-8 schema bytes per process, `serialized_input_bytes = prompt_bytes + schema_bytes`. Card bytes sum item attempts. |
| `accounting` | Exactly `call_accounting(calls)`: top-level counters summed once per call only when present on every call; otherwise null. Paid cost stays unavailable without a separate invoice-backed accounting extension. |
| `execution` | Historical `checkout_root`, execution `git_sha`, run start/end monotonic nanoseconds, archived fingerprints for runner/scorer/validator/service/prompt/card builder, and `cleanup` recording zero owned children, stopped helper and any cleanup errors |
| `http_history[]` | Unique `event_id`, operation (`claim`, `submit`, `release`, `cancel`, `renew`, `preview`), request/response artifacts, status/error, monotonic start/end and `resend_of`. An identical resend gets a new event and points to its predecessor; a new reasoning retry gets a new attempt and call. |
| HTTP artifact bodies | Request JSON wrapper `{method,url,headers,body}`; response wrapper `{headers,body}`. `body` retains the parsed JSON or raw response text when parsing fails. | `state_artifacts` | `registry`, `before_snapshot`, `after_snapshot`, `before_db`, `after_db`, `apply_journal`, `source`, `upgraded`, `corpus_heads`. See the format below. |
