## 1. Architectural Role: TnT-LLM for Personal Media

The Living Library organizes spoken audio, video, and saved posts into a navigable 3-level taxonomy. Operating over raw transcripts (which average 25,000–60,000 tokens for podcasts and long videos) across hundreds of items would be prohibitively slow and expensive ($8–$80 per catalog pass, days on local models).

We adopt the **TnT-LLM (Two-stage Taxonomy Induction and Assignment)** methodology:
1. **Taxonomy Induction (Stage 1)**: Executed infrequently (e.g., initially, or when unmapped queues accumulate). A capable frontier model (Sonnet 5, Gemini 3.8 Pro, or GPT-6) analyzes a stratified sample of evidence cards to generate or update the global taxonomy tree.
2. **Taxonomy Assignment (Stage 2)**: Executed nightly or on ingest. Fast, lightweight local models (Qwen 3.8 27B / 35B MoE) or cost-effective batch cloud models (Claude Haiku 4.5, Gemini 3.8 Flash) classify new evidence cards into existing leaf shelves with verbatim evidence quotes.
3. **Concept Re-Shelving (Emerging Concept Pass)**: Executed when a new concept crystallizes (burst detection, user addition, or split). Historical evidence cards are evaluated against the new leaf node to backfill items that discussed the idea before its vocabulary was standardized.

## 2. The Evidence Card Substrate

All three prompts consume **Evidence Cards** generated by `uoink_mcp_tools.get_evidence_card` rather than full transcripts. 

### Structure of an Evidence Card
Each evidence card contains:
- `video_id`: Canonical internal ID.
- `slug`: Human-readable identifier.
- `title`: Item title.
- `channel`: Author or channel name.
- `platform`: Origin platform (`youtube`, `podcast`, `x`).
- `summary_hint`: The first ~600 characters of cleaned markdown body prose (omitting headers, image embeds, and metadata blocks).
- `clips`: Up to 10 timestamped transcript windows (45–120 seconds each) selected via timeline binning (taking the longest, highest-information clip in each segment).
- `clip_count`: Total clips available for the item.
- `chars`: Total character volume across all clips.

### Token Economy
An average evidence card consumes 750–1,100 tokens.
- 60-card sample for induction: ~55,000 input tokens (~$0.16 on Haiku batch; ~$0.55 on Sonnet).
- 500-item full assignment pass: ~450,000 input tokens + ~40,000 output tokens (~$0.65 on Haiku 4.5 batch).
- Comparison: Raw transcript passes over 500 items would exceed 15,000,000 tokens ($15–$50).

## 3. Prompt Specifications

### 3.1 Taxonomy Induction (`scripts/librarian/prompts/induce.md`)

* **Purpose:** Proposes or updates the library's hierarchical shelf system from a representative sample of evidence cards.
* **Input Placeholders:**
  * `{{CARDS}}`: Formatted JSON array or markdown blocks of sampled evidence cards across platforms, channels, and durations.
* **Refusal & Structural Rules:**
  * **Hierarchy Depth:** Exactly 1 to 3 levels: `[Top Shelf, Sub-Shelf, Leaf]`. Leaves are optional for smaller categories.
  * **Shelf Counts:** 5 to 9 top shelves. 2 to 6 sub-shelves per top shelf.
  * **Volume Threshold (Refusal Rule):** Prohibit any top-level shelf supported by fewer than 5 items in the sample. Sparse topics must be merged into broader umbrellas.
  * **No Miscellaneous Shelves:** Strictly reject generic fallback buckets ("Other", "Misc", "Uncategorized").
  * **Tone:** Natural terminology used by practitioners (e.g., "Developer Tools", "Coding Assistants", "Agent Harnesses").
* **JSON Schema (`INDUCE_SCHEMA`):**
```json
{
  "type": "object",
  "properties": {
    "nodes": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "path": {
            "type": "array",
            "items": {"type": "string"},
            "minItems": 1,
            "maxItems": 3
          },
          "definition": {"type": "string"},
          "include": {
            "type": "array",
            "items": {"type": "string"},
            "minItems": 2,
            "maxItems": 8
          },
          "exclude": {
            "type": "array",
            "items": {"type": "string"},
            "maxItems": 4
          }
        },
        "required": ["path", "definition", "include", "exclude"],
        "additionalProperties": false
      },
      "minItems": 10,
      "maxItems": 120
    }
  },
  "required": ["nodes"],
  "additionalProperties": false
}
```

### 3.2 Taxonomy Assignment (`scripts/librarian/prompts/assign.md`)

* **Purpose:** Categorizes individual evidence cards into existing shelves during nightly batches or upon ingest.
* **Input Placeholders:**
  * `{{TAXONOMY}}`: JSON representation of current nodes (path, definition, include, exclude).
  * `{{CARDS}}`: Batch of evidence cards to file (typically 10–25 items per model call).
* **Refusal & Grounding Rules:**
  * **Anti-Hallucination Guardrail:** Never assign on title alone when clips are present. Titles often use clickbait phrasing that contradicts the actual lecture or episode content.
  * **Verbatim Evidence Requirement:** `evidence_quote` must be an exact substring (< 25 words) from one of the clips in the card. No paraphrasing.
  * **Metadata-Only Fallback:** If `clips` is empty or null, set `evidence_quote: "metadata-only"`, assess title and channel, and cap confidence at 0.85.
  * **Confidence Floor & Unmapped Queue:**
    * If confidence < 0.60, or no leaf node fits the subject matter: mark `unmapped: true`, leave `shelf_paths: []`, and specify `proposed_new_leaf` formatted as `"Top > Sub > Leaf"`.
    * If confidence >= 0.60: mark `unmapped: false`, provide 1 to 3 valid paths, and set `proposed_new_leaf: ""`.
* **JSON Schema (`ASSIGN_SCHEMA`):**
```json
{
  "type": "object",
  "properties": {
    "assignments": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "video_id": {"type": "string"},
          "shelf_paths": {
            "type": "array",
            "items": {
              "type": "array",
              "items": {"type": "string"},
              "minItems": 1,
              "maxItems": 3
            },
            "minItems": 0,
            "maxItems": 3
          },
          "confidence": {"type": "number"},
          "evidence_quote": {"type": "string"},
          "unmapped": {"type": "boolean"},
          "proposed_new_leaf": {"type": "string"}
        },
        "required": ["video_id", "shelf_paths", "confidence", "evidence_quote", "unmapped", "proposed_new_leaf"],
        "additionalProperties": false
      }
    }
  },
  "required": ["assignments"],
  "additionalProperties": false
}
```

### 3.3 Emerging Concept Re-Shelving (`scripts/librarian/prompts/reshelve.md`)

* **Purpose:** Evaluates historical items against a newly defined concept node to identify prior instances and update library filing.
* **Input Placeholders:**
  * `{{CONCEPT}}`: Specification of the emerging node (`path`, `definition`, `include`, `exclude`, `coined`).
  * `{{CARDS}}`: Historical cards filed before the new shelf was established.
* **Evaluation Criteria:**
  * **Substantive Coverage Only:** The item must engage with the concept substantially. Incidental mentions or tool invocations do not meet the bar.
  * **Temporal Precursors:** Items created before the formal coining date are assessed on functional equivalence (e.g., executing agent loops with bash scripts before "loop engineering" was named).
  * **Verbatim Verification:** If `belongs: true`, quote the exact phrase demonstrating the pattern. If `belongs: false`, quote the phrase confirming what the video is actually about.
* **JSON Schema (`RESHELVE_SCHEMA`):**
```json
{
  "type": "object",
  "properties": {
    "verdicts": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "video_id": {"type": "string"},
          "belongs": {"type": "boolean"},
          "confidence": {"type": "number"},
          "evidence_quote": {"type": "string"}
        },
        "required": ["video_id", "belongs", "confidence", "evidence_quote"],
        "additionalProperties": false
      }
    }
  },
  "required": ["verdicts"],
  "additionalProperties": false
}
```

## 4. Worked Example: Emerging Concept "Loop Engineering"

To illustrate the re-shelving trigger and execution, consider `scripts/librarian/prompts/concept-loop-engineering.json`:

```json
{
  "path": ["AI and ML", "Agent harnesses", "Loop engineering"],
  "definition": "Putting an AI coding agent on repeat: the practice of designing the loop an agent runs in (discovery, handoff, verification, persistence, scheduling) rather than the single prompt, so work continues across sessions, checks itself, and runs unattended.",
  "include": [
    "loop engineering",
    "run the agent in a loop",
    "put the agent on repeat",
    "agent loop",
    "ralph loop",
    "harness engineering",
    "scheduled agent runs",
    "cron for agents",
    "long-running agent",
    "verification step in the loop",
    "persistence across context windows",
    "autonomous overnight run"
  ],
  "exclude": [
    "single-shot prompting tips",
    "prompt engineering without a loop",
    "for loops in code tutorials"
  ],
  "coined": "Addy Osmani, 2026-06-07 (addyosmani.com/blog/loop-engineering; O'Reilly republish 2026-06-22)"
}
```

### Trigger Scenario
1. **Detection:** The Analyst or user notices a term burst: "loop engineering" appears in multiple June 2026 posts and videos.
2. **Node Creation:** The user or Librarian defines the new leaf node above.
3. **Candidate Selection:** uoink queries the index for historical items under `["AI and ML", "Developer Tools"]` and `["AI and ML", "Agents"]` yoinked prior to June 2026.
4. **Model Verdicts:**
   * **Item `_3GaXHNSP2I` (ThursdAI Apr 2, 2026):**
     * Verdict: `belongs: true` (confidence 0.94).
     * Evidence quote: `"It's just that Claude is a good model. If you run it in a loop it becomes magical."`
     * Action: Co-filed onto `["AI and ML", "Agent harnesses", "Loop engineering"]`.
   * **Item `zYGDpG-pTho` (IBM RAG vs Fine-Tuning):**
     * Verdict: `belongs: false` (confidence 0.98).
     * Evidence quote: `"Three ways to get better outputs out of large language models, each with their pluses and minuses."`
     * Action: Remains on existing shelf; no change.

## 5. Stability, Churn, and Safeguards

1. **Threshold Holdout:** New shelves proposed by the unmapped queue remain staging proposals until at least 5 distinct items match the concept over two separate passes.
2. **User Pinning:** If a user manually assigns or moves an item to a shelf, the database marks the assignment with a user lock. The Librarian never overwrites or un-shelves locked rows.
3. **Safe Churn Rate:** A re-shelving pass that moves more than 15% of the back catalog automatically pauses and flags a warning report for human review before persistent commits.
