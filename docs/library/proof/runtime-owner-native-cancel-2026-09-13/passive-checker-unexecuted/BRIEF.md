# Passive native-owner receipt checker

check_receipts.ps1 is prepared but unexecuted. After the separately admitted native observation, root may run it with the exact original admission hash supplied as ExpectedAdmissionSha256. The checker creates no admission, run directory or evidence file. It prints a result only after all checks pass; failures propagate as errors. Actual outer-tool provenance remains root's separate responsibility.

The fixed read set is 74 existing text files: 29 original/copied source pairs, three original/copied control pairs, eight JSON receipts and two logs. EXPECTED-READS.json lists every path. The inherited reader requires strict UTF-8, no NUL, ordinary files, no reparse ancestors and a one-MiB per-file bound. It checks original/copied and before/after hashes, then rereads its exact read set at the end. No path taken from a receipt is opened. Support and fixture paths are compared only as recorded metadata. The physical journal, checkpoint and converted D2 output are excluded.

The preserved PowerShell checker supplies the existing source, guard, dispatch, cancellation, journal, process/job, adoption, startup and generated readback checks. The new source names and schema are fixed to the reviewed native proposal. The old observation's actual-tool identifiers and admission hash cannot describe a future run: tool provenance is excluded, and the caller supplies the future admission hash. The old journal's post-observation size/hash constants are replaced by the launcher's existing size bound and independent checks of the recorded bytes. Record lengths are decoded; no old PID-dependent prefix length or future digest is invented.

The added decoder reads only journal_hex already inside controller-result.json. It checks four bounded frames, their SHA-256 digests, canonical record text, sequence, predecessor links, fixed phases/semantics, generation and process consistency, complete consumption and final head. It hashes the actual third-record prefix and compares it to the unchanged WORKER_BOUND cancellation observation. It derives the journal filename only to compare recorded strings.

The owner checks require six unchanged binding guards, all 19 receipt fields, the exact 16 bridge events and five generated factory events, one segment, factory retirement and logical revocation. The returned owner receipt must equal the retained child receipt; this checks recorded bindings, not object identity reconstructed from JSON. Complete inherited-member identities, manifest digest and exact policy acknowledgement are checked without reopening a member.

This is a passive consistency check of saved evidence. It executes neither the candidate journal decoder nor any candidate module, and establishes no fresh kernel observation, native memory reclamation, real inference, restart recovery or release approval. No checker, candidate or native invocation occurred during preparation.
