## Exact proposed inspection

Review `read_checkpoint_inventory.py` before allowing any artifact read. It
uses only the Python standard library and has one hardcoded input path. It
rejects observed linked/reparse components below the checkout, non-regular files, changed file identity,
and an existing output receipt. A single opened stream supplies the full-file
SHA256, directory inspection, and bounded pickle bytes. No archive member is
extracted to disk.

The reader permits ZIP_STORED and ZIP_DEFLATED only. It checks the ordinary or
ZIP64 end records before ZipFile builds its directory, rejects split/encrypted
archives and conflicting offsets/counts, and checks member names, bounds,
local-header spans, duplicate names, overlapping member regions, and symlinks.
It scans actual central-directory entries before ZipFile allocates them; ZIP
minimum-reader versions above 4.5 and unsupported directory records are refused.
It refuses a non-ZIP checkpoint, unsupported formats, ambiguous pickle members,
or a pickle member whose advertised or actual size exceeds its limit.

Limits are chosen for this inspection, not inferred checkpoint properties:

| Resource | Limit |
|---|---:|
| Whole file | 256 MiB |
| ZIP central directory | 2 MiB |
| Members | 256 |
| One member's uncompressed size | 256 MiB |
| Sum of advertised uncompressed sizes | 512 MiB |
| One member name | 256 UTF-8 bytes |
| One local/central extra field / member comment | 8 KiB / 1 KiB |
| Pickle payload, compressed and uncompressed | 2 MiB each |
| Compressed pickle expansion ratio | 100 |
| Pickle opcodes | 250,000 |
| Recorded GLOBAL literals / string samples | 64 each |
| Saved JSON receipt | 256 KiB |
| Work between elapsed-time checks | 30 seconds total |

The time budget is cooperative: checks occur between bounded reads and parsed
opcodes; this is not an OS-level deadline for a stalled filesystem operation.
The reader never decompresses tensor/storage members. Hashing reads their
opaque bytes as part of the one allowlisted file.

For the pickle member alone, bounded stdlib zlib decompression requires exact
declared size, a completed stream, no remaining compressed data, and matching
CRC before any opcode parsing. Stored pickle bytes get size and CRC checks too.

For a single small `data.pkl`, `pickletools.genops` reports opcode counts,
literal GLOBAL references, bounded identifier-like string samples, and counts
of stack-global, persistent-ID, object-construction and reduction opcodes. It
does not resolve a global, evaluate the pickle stack, construct an object,
resolve a persistent ID, import a checkpoint-named module, load a tensor,
convert a model, or execute captured code. Trailing bytes after STOP are refused.

## Receipt and interpretation

The integrator confirmed that this read-only static inspection is within Ryan's
existing product-security authorization; it requires no new Ryan permission.
The integrator must review the exact reader before the artifact is opened. The
intended invocation is the reviewed Python executable with
`-I -S -B read_checkpoint_inventory.py --inspect --run-id run01`, from this directory
or with the reader's absolute path. The caller must retain the real shell exit.
The reader writes that intended exit in a fresh local JSON receipt: 0 means the
bounded static inventory completed, 2 means a supported refusal, and 3 means an
unexpected reader failure. A receipt-write failure returns 4 and reports that
no successful receipt was written. No refusal or parsing failure is a pass.
Argument-validation errors return the parser's real exit without an inventory
receipt. An occupied receipt path is refused before input inspection; because
that receipt cannot be replaced, the reader reports exit 4 on stderr. There is
no retry, repair, archive extraction, or download fallback.

A hash binds observed bytes. A list of pickle globals is a list of literal
references, not an allowlist or proof of safe execution. STACK_GLOBAL is counted
without claiming that adjacent strings identify its target. Opcode parsing
does not establish pickle semantics, a compatible fixed architecture, tensor
shapes, checkpoint provenance, quality, native-library behavior, safe conversion,
or release readiness. Those remain separate reviewed decisions and protocols.
Path and file-identity checks detect observed changes, but do not establish an
atomic filesystem snapshot against a hostile concurrent writer. Inspection
requires the staged artifact and its path ancestors to remain quiescent.
