# Reporting-only repair for the static inventory refusal

The integrator's single authorized static inspection, `run01`, refused the
archive at a central-directory compatibility check. Its receipt and launcher
result record reader exit 2; the integrator reports the enclosing exec returned
1. The reader hashed 17,719,103 bytes with SHA256
`0b5b3216d60a2d32fc086b47ea8c67589aaeb26b7e07fcbe620d6d0b83e209ea`.
It did not reach pickle inventory. This remains a refused inspection, not a
passed artifact check or evidence about checkpoint architecture.

The refusal message, `Unsupported or split ZIP directory entry`, omits the
numeric header values that distinguish unsupported version from a split
archive. This reporting-only repair will attach bounded integer fields:
one-based entry ordinal, central-header byte offset, needed version, disk,
compression method, flags, raw advertised sizes, name/extra/comment lengths,
and raw local-header offset. It will not include member names or pickle data.
No accepted format, predicate, resource bound, read extent, decode behavior,
or output destination changes. The same archive must still be refused.

The original 27-payload seal was fully verified and copied before revision.
The original proposal, reader and seal remain untouched. The refused receipt,
root launcher and four launch logs are copied under `preserved-run01` without
the checkpoint. `preservation.json` records this boundary and the original
executed-reader hash. New code is confined to this fresh proposal directory.

After the reporting change, a fresh `static-reporting-preflight01` will run
under `-I -S -B`. It retains all 36 existing synthetic behavior assertions,
adds exact numeric-context assertions for refused directory entries, disables
reader `inspect`/`main`, and prohibits opening the checkpoint. Containers and
pickle literals remain in memory; no pickle is executed. Source/setup diffs
and the real qualification exit must be preserved. No actual artifact read
or reader-main invocation is authorized for this subagent.
Static AST comparisons will also require unchanged refusal predicates/messages,
top-level constants and file-read call expressions against the preserved
executed reader. They support the reporting-only claim without executing
either reader's input path.

The new reader deliberately retains the same fixed input and receipt root:
`_scratch/vad-static-inventory-proposal01/results`. A later fresh run ID there
requires the integrator's exact-reader review and execution; this task does
not run it. Numeric format metadata may support a later compatibility
decision, but cannot authorize a relaxed loader, deserialization, model load,
conversion, inference, download, frozen-stack change, or release acceptance.

This brief precedes the reporting edits and their synthetic qualification.
