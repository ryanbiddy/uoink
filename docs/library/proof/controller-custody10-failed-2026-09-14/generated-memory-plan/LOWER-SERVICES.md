# Required lower-service adaptation

Use the captured `test_windows_reservations.py` as a storage-algorithm donor, not a complete fixture. Its Disk/FakeAPI (48–102) supplies the bytearray, position, short read/write and exclusive-owner pattern. Its FakeFFI (18–45) lacks typed array/byref behavior; FakePrimitives pins exactly five members and bypasses the actual identity query. The no-worker port setup (378–392) explicitly has no process/pipe service. These bodies and the accepted95 fixture stay unchanged. No complete existing inert donor was found in the selected directory.

The new fixture should adapt those algorithms into these finite services:

- **Typed data objects:** distinct scalar classes for c_uint32, c_int64, c_size_t and c_void_p; byref objects exposing `_obj`; a char Array with `_type_ is c_char`, exact raw capacity and sizeof; unicode buffers; handle arrays via scalar-type multiplication; the fixed structure fields read by the actual primitives and pipe code; one registered attribute-buffer cast. This is a pure Python data protocol, with no ctypes or claim of ABI qualification. Do not alias all scalar types to the old Cell.
- **Files and identities:** fixed directory/ASCII-member/journal nodes, exact paths and stable identities, size from stored bytes, reparse/delete/link facts, per-open offset and access/share/disposition. CREATE_NEW actually inserts an empty memory node. Controller and contender opens share the same physical journal key. Duplicate/inherited handles retain access/share ownership across parent duplicate closure. An inherited child handle is a distinct namespace entry even when its integer matches the parent's.
- **Process and job state:** create a fresh simulated process/thread pair from retained process output structures, attach only the actual explicit inherited-handle list, enforce one process per job, maintain fixed creation time, and implement resume/exit/active-count queries. Actual `create_suspended_worker` sets the product WorkerRecord fields from those results. No fake assigns them. Parent duplicates close without removing child copies. A failed target's remaining simulated handles close only when that target has actually ended; retained product uncertainty stays visible.
- **Byte pipes and events:** one duplex pipe, distinct inherited endpoint, event/OVERLAPPED records keyed by exact objects, bounded pending connect/read/write, completion byte counts, cancellation and endpoint retirement. Connect must first produce ERROR_IO_PENDING; the client open completes that specific request. Completion follows real queued bytes or a terminal channel error, not unconditional success. Actual `PrivatePipeController` owns every PendingIO/buffer and retires it through its unchanged methods.
- **Journal observation:** synchronous seek/read/write update offsets/output counts and the shared bytearray. Successful FlushFileBuffers invokes actual setup observation; revision/head/confirmed bytes come from actual journal methods. Recursively invoked identity queries remain allowed only for fixed retained owners. The ordinary close observer runs before the backend closes the journal.

The planned API names are listed centrally in SOURCE-BINDINGS.json. Refuse undeclared names, arbitrary paths/targets and unowned handles. Keep the source's chunk, journal-event and wait bounds. Use a finite per-case call ceiling; it is a test runaway bound, not a product latency guarantee.

Actual inherited adoption still clears five flags and queries all five identities. The close-before-begin branch releases those owners without content readback.
