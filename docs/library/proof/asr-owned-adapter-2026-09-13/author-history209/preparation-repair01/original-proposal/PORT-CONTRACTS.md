2026-09-13. These are exact interfaces required by asr_loading_adapter.py. None of their real implementations is installed or supplied by the proposal. The globals stay None; ordinary caller arguments cannot replace them.

Release authority is a reviewed bootstrap object containing immutable manifest bytes, the identical resolver REAL_APPROVAL object, one canonical local Windows data_root and an accepted runtime profile ID. The adapter derives only data_root/model_assets/asr/<choice>/<revision>. Transcription's data_root must match the bound root; reliability's old model_root must equal data_root/models/whisper. The old root is a caller-context check, not an asset search path. Settings, client JSON, .pt markers, Hub refs, the acquisition service and successful file hashes cannot mint release approval. Complete SHA-256/size records are required before acquisition; the current missing twenty hashes remain a blocker.

SNAPSHOT_LIFECYCLE.read_lease(store_root, choice, revision) returns a context manager. Before granting a lease it must validate the root/ancestors, enforce containment and coordinate all publishers/repairers. The returned token implements begin_native_session() and confirm_native_closed(). No writer, deletion, replacement or cleanup may affect a leased snapshot. A lease with begun but unconfirmed native work must stay quarantined on exit, even when __exit__ receives no exception information; ExitStack.close() is used. It must never suppress an exception. Persistent recovery must reconcile a crashed worker and unknown native handles before allowing reuse/deletion. The lease is required for the entire generator/model lifetime, not just construction.

An in-process mutex or metadata receipt alone does not satisfy that contract. A concrete Windows design must hold file/ancestor authority and exclude write/delete/reparse changes across native path reopen, or construct from a separately protected immutable snapshot that provides equivalent guarantees. Evaluate exact handle sharing and directory behavior under a separately reviewed isolated kernel protocol. Ordinary user/admin processes, filesystem changes and crash recovery are not made safe merely by naming this object a lease. If the manager cannot establish the required boundary, acquisition/runtime remain unavailable.

ACQUISITION_SERVICE.acquire_and_publish(plan, consent_given=True) accepts the frozen AcquisitionPlan fields: exact choice/repository/revision/manifest digest, predetermined destination, complete Asset tuple and logical byte sum. It performs no model imports/construction. It must take a writer lease, refuse existing redirects/unknown data, stage only the approved names in a private incoming location, enforce individual/aggregate transfer/hash bounds, reject unapproved redirects, verify all bytes and atomically publish the expected immutable directory. Publication cannot modify a reader's snapshot. It must not turn a model name into moving Hub resolution, use a global cache, expand scope, accept unknown hashes or grant manifest authority. Its returned value/path is deliberately ignored. The adapter performs fresh admission under a new read lease and invokes the service at most once per explicit request. A constructor/inference/cleanup failure never enters this acquisition handler.

RUNTIME_FACTORY.open_owned_session(profile) may run only after manifest admission and lease.begin_native_session(). The factory must first bind the accepted interpreter, wheels, DLLs and fixed source profile, then perform the approved import/decoder-registration sequence. It returns a managed runtime with whisperx_load_model(path, device, compute_type, vad_model, local_files_only), faster_whisper_model(path, device, compute_type, local_files_only), make_fixed_vad(contract), verify_capture_vad_contract(contract) and close_and_join(). It may not resolve arbitrary module/class names from artifacts or caller input. It owns every model, VAD, DLL handle, decoder and asynchronous native operation that it creates, including failed constructors. close_and_join() returns exactly True only when all owned work and asset references are finished. False, None, exceptions or a failed factory with no returned owner leave the lease unconfirmed and quarantined. That is an explicit unavailable/error state, not a successful release.

Before any Torch/package import, the owned process startup must set and verify TORCH_DEVICE_BACKEND_AUTOLOAD=0. Exact Torch 2.13 source cf40c075c95864036e835795756d69b8cccfafa76f3bcde5eba9d06065ccd3d1 (release cf30153, retained body-04.txt lines 3017-3077) otherwise discovers and loads torch.backends entry points by default. Setting the value after import is too late. This is one explicit startup gate alongside controlled import paths and the approved distribution/profile; it does not establish that every native import is safe. The adapter does not import Torch or supply the real startup implementation.

RuntimeProfile is accepted external policy, not a user preference. Its profile ID must equal the release's ID; its current proposed device is CPU and its exact int8/float32 choice must come from qualified policy. This is the owner's existing first-qualification CPU scope, not a new GPU compatibility claim. WhisperX requires a named fixed plain-state VAD contract and an actual non-None VAD injection. The existing reliability capture path retains vad_filter=True, so capture_fallback additionally requires an accepted contract for the exact bundled VAD resource or a separately implemented equivalent. A contract string is only a reference to the reviewed runtime policy; by itself it proves no safety. Ordinary reliability scoring has no enabled VAD filter and does not inherit that optional approval.

Caller code must consume all lazy segments inside the returned context and must not retain a model/generator beyond it. The future owned runtime should expose an operation facade or worker boundary if ordinary object references cannot be controlled. The adapter's cleanup protocol and product call-site discipline do not prove that arbitrary callers cannot retain objects.
