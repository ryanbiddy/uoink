# Two fixed filterbank buffers as an endian validation basis

2026-09-13. Assess a separate, explicitly chosen compatibility check for the two persistent filterbank buffers. Work from retained source text and generated bytes only. The frozen converter, its unavailable real profile and all original receipts remain unchanged. No actual checkpoint, storage, model, tensor or package is read or executed.

The retained ParamSincFB source creates `window_` from the first 125 samples of a 251-point NumPy Hamming window, cast to float32. It creates `n_` from indices -125 through -1 divided by 16000, then multiplied by 2*pi. SincNet fixes the 251 kernel and 16000 sample rate. The reviewed metadata records `window_` as storage 4, shape [125], offset 0, and `n_` as storage 5, shape [1,125], offset 0, each with 125 declared elements and 500 advertised bytes. They are registered buffers rather than the two learned filter parameters. Registration does not prove that a training program, hook or checkpoint editor never changed them.

Propose a small pure stdlib comparator accepting only two immutable 500-byte strings. Generate the analytic references with Python math and round each expected number to IEEE binary32 using struct. Compare every candidate word under both little- and big-endian interpretations against its ordered reference. Require finite values, matching signs, and at most eight representable float32 steps from the rounded reference for every one of the 250 words. Require exactly one orientation to satisfy both complete buffers. A mismatch, incompatible length/type, ambiguous result or nonfinite value refuses the basis. Do not select orientation by aggregate plausibility, majority vote or a best score; do not tune the tolerance after seeing real bytes.

Eight float32 steps are a proposed fixed compatibility tolerance, not a measured historical numerical bound. The n_ expression can round after division, when casting a scalar and after multiplication; the proposed margin allows those ordinary operation-order differences. The Hamming reference uses a cosine expression and a final float32 rounding. This task must identify the retained source versions and distinguish the analytic formula from an authenticated reconstruction of historical NumPy/Torch behavior. It does not prove that every past backend necessarily fits the tolerance; an actual mismatch must remain a refusal.

Synthetic qualification will cover both unambiguous orientations, both buffers being required, all four inclusive tolerance boundaries, just-outside boundaries, altered order, NaN/infinity, exact size/type limits and the explicit neither/both decision guard. The latter may use a direct decision-helper case rather than claim an ambiguous full fixed-buffer fixture exists. Run only the generated-byte comparator under -I -S -B, explicit forbidden-live startup binding, provider scrub and a closed audit guard. Preserve every actual failure and use a written repair with a fresh label before repeating a run.

The eventual real protocol would separately need fixed artifact identity, full ZIP/member spans and CRC checks, exact storage references/sizes, an observed archive/version and reviewed permission to inspect these 1000 bytes. A successful comparison would establish compatibility with this chosen source-invariant basis. It would not authenticate the writer platform, prove all other storages have the same endian encoding, authorize a model run, establish numerical equivalence or approve conversion. A uniform-storage-encoding assumption must be explicitly supported by the pinned raw-storage writer contract and accepted as part of that future protocol.
