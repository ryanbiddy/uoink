# Proposed isolated qualification stages

This is a future protocol for Ryan to authorize by scope. No stage was run in this source review. Each stage needs a brief, frozen inputs, resource limits, fresh receipts and a reviewer verdict. Failure or missing evidence leaves that gate open.

1. **Identify the artifact and choose acquisition or conversion.** Ryan decides whether to authorize a specific upstream plain-state export/configuration fetch or a restricted conversion project for the exact artifact in the existing receipt. Record license, release/source identity, bytes/hashes and custody. Establish architecture and complete configuration from authoritative data and independently reviewed source. Do not infer them from sampled tensor names. If unavailable or contradictory, stop this stage; no generic load is permitted to discover the answer.

2. **Review the converter or export without executing the old model.** If conversion is needed, review its exact supported grammar and refusal behavior before running it. Test the converter with inert synthetic archives in an isolated worker: unknown/rebound globals, reducer/new-object/build instructions, forged persistent IDs, cycles/alias ambiguity, duplicate ZIP names/JSON keys, oversized records, invalid shape/stride/offset/byte-order data, truncated storage and trailing data. Record every refusal and resource limit. Permit only a reviewed nonexecuting translation into plain metadata and dense tensor bytes. Never add blanket globals or an unsafe fallback when a case fails. Opening/converting the real checkpoint is a separate authorized action after this stage, with source/derived artifact hashes and a second independent check. If a trusted exporter exists, its provenance and exact format/schema still need review; file naming is insufficient.

3. **Qualify the fixed loader with synthetic assets.** Use a new disposable VM/profile with no host data, credentials, user cache, live index or shared writable project directories. Deny network at the OS level; never permit port 5179. Use a reviewed dependency/runtime bundle and an unprivileged process with memory/time bounds. Instrument attempted checkpoint loads, model fetches, dynamic imports and native imports before collection. Independently establish that missing/bad/draft manifests, changed bytes, path escape/reparse swaps, state key/dtype/shape errors, nonfinite values and unsupported devices fail at the specified boundary. Test exact pre-constructor/pre-allocation refusals. Include a successful fixed synthetic model case and inspect raw logs, results, exit status and guard health. Existing acceptance assertions remain unchanged. Python mocks alone do not establish a native or child-process boundary.

4. **Build the exact factory and validate the approved plain state.** Only after Ryan authorizes native model construction, use the same contained environment, fixed source/dependency hashes and approved tensor bytes. Set `PYANNOTE_METRICS_ENABLED=0` before imports and retain OS network denial; source shows telemetry infrastructure is created at import despite that flag. Record the factory's complete parameter/buffer schema and compare with an independently reviewed schema. Require strict load, exact types/shapes/dtypes and bounded memory. Record no fallback, no unexpected import/fetch, raw stdout/stderr and process/guard outcomes. An accepted load is a structural result, not a quality result.

5. **Qualify VAD behavior against a frozen reference.** Obtain a trusted numerical/reference output set or separately authorize a disposable legacy-oracle experiment. The current task authorizes neither. Never execute the unsafe old loader on Ryan's ordinary profile to generate that oracle. Fix comparison tolerances before measurement. Test silence, speech, very short audio, padding at chunk boundaries, long speech crossing the min-cut limit, variable lengths, stereo downmix/resampling and malformed inputs using explicitly authorized local fixtures. Compare intermediate frame counts/geometry, score values, speech intervals and merged chunk boundaries; report deviations and absolute errors, not just a load success. Exercise the WhisperX injected-object path and all six ASR choices with inert seams first; any real ASR/model exercise needs its own authorized artifact scope. Do not run diarization or make speaker claims.

6. **Qualify each proposed runtime and release the derivative.** Test the current and proposed dependency stacks separately only after their graph/advisory/import gates permit that trial. Preserve exact Windows/Python/CPU/GPU/DLL versions, memory/time observations, raw fail/pass counts and commit IDs. No cap relaxation or `strict=False` repair can turn a failure into acceptance. Have the council and integrator review the export, fixed implementation, negative tests and numerical results. Then a new product brief may wire the fixed loader, preserve six model choices and the consent policy, rebuild the candidate and rerun prescribed suites. Installer receipts, other security findings and speaker restrictions retain their own status.

Ryan's decision points are artifact acquisition/conversion scope, any execution of a legacy numerical oracle, and the contained native/model trials. This proposal neither requests a main merge nor grants a download, installation or execution authorization.
