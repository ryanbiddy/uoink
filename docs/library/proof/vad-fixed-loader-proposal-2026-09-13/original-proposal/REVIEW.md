# Default VAD: fixed loader proposal

2026-09-13. Source review only; no checkpoint was opened or converted, no model module was imported, and no tensor or inference was run. Parent reports tree09 running at `56d9d4c`; this scratch proposal does not change its inputs.

Use a reviewed factory with an approved plain tensor artifact, then inject its VAD pipeline through `whisperx.load_model(vad_model=...)`. The inspected source supports that route. The missing prerequisite is a verified mapping from the bundled checkpoint to its architecture, constructor values, task settings and tensor state. The static inventory does not provide that mapping. This proposal therefore cannot yet supply a working replacement or close the VAD release blocker.

The first choice is an authoritative export containing a dense tensor state and reviewed plain JSON settings. A restricted, nonexecuting conversion is a possible separate engineering project if no such export exists. Neither a hash check followed by the existing unsafe load nor a blanket `safe_globals` list is an acceptable shipped repair.

## Migration choice and remaining evidence

**Preferred: fixed factory plus an authoritative plain-state export.** Obtain an export and configuration bound to the exact intended model/version, with license and provenance. Have a reviewer establish every factory and specification value independently. Export only the inference parameters and buffers in a non-pickle tensor format; keep training metadata out. Freeze the resulting schema, artifact bytes and manifest identity in the shipped release. Application code selects the single factory; artifact data cannot select imports, classes, hooks, devices, fetches or fallback loaders. A new upstream fetch requires a separate brief and Ryan's scope decision.

**Fallback: restricted, nonexecuting conversion.** The existing receipt records protocol 2, 21,882 bytes of `data.pkl`, 17 literal `GLOBAL` instructions, 327 `REDUCE`, nine `NEWOBJ`, nine `BUILD` and 160 `BINPERSID`. It explicitly says pickle semantics and persistent IDs were not resolved. A converter would need to establish the actual graph, storage references, offsets, shapes, strides, byte order and aliases while representing any legacy objects as inert data. It must never import a referenced global, invoke a reducer, construct a pickle-selected object or call a persistent-load callback. That is substantially more work than token inventory. Prefer a separately reviewed existing converter with a demonstrably sufficient, restrictive grammar; this task implements no parser. Unsupported or ambiguous records must stop conversion. If a numerical oracle requires executing the legacy loader, that is an additional isolated experiment requiring its own authorization, never an implicit converter fallback.

The receipt is bound to artifact SHA-256 `0b5b3216d60a2d32fc086b47ea8c67589aaeb26b7e07fcbe620d6d0b83e209ea` and size 17,719,103 bytes. Those values are **reported by the prior inventory**, not remeasured here. Its JSON SHA-256 is `703df7add11e0d9bd0f50eac6e20da0e0477479ae46f749b5eacfd532cb51b5d`. It has no architecture claim. It does not establish constructor values, recovered task fields, tensor membership, finite values, compatibility, numerical behavior or conversion viability. The 17 globals are not an allowlist.
