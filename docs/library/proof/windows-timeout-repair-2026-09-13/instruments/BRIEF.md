# Timeout repair documentary seal proposal

This instrument copies and verifies saved text only. It never imports or executes archived source, invokes a test/native worker, reads installed support binaries, or touches model/product data. Root must review the builder and verifier before executing them.

The fixed inventory contains both timeout proposals and their retained drafts, both complete generated native run directories, author/root synthetic inputs and raw results, and eight actual root tool objects. The original generated 64-byte guard fixture is text and remains bound to each run. Installed Python/System32 identity appears only in retained JSON receipts; those files are not reopened.

The implementation follows the reviewed `dummy-native-combined-proof-proposal01` builder/verifier pattern (builder 066be67a, verifier 0ce9de3f), with timeout-specific outcome assertions. Identical text is stored once as `objects/<sha256>.txt`; every logical source path maps to its exact bytes. The fixed inventory is hashed into both instruments. The builder verifies its copied physical files and writes that receipt before sealing the exact final file set. The verifier then independently checks physical membership, source mapping, native failures/success, all bindings, both complete 67-case lists and raw exits. It produces no archived-code execution.

Output is a fresh `_scratch/timeout-repair-proof01`, with `* -text`. No file is added after `MANIFEST.json`; the actual builder/verifier tool objects belong outside the frozen proof unless root deliberately creates a new enclosing seal. No result is regenerated or relabeled.
