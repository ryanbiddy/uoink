# Integration ports and ownership

This proposal implements orchestration for generated bytes. The injected ports are trusted test code, never callbacks, module names or classes selected by an artifact. Arbitrary Python callbacks can perform arbitrary effects; the synthetic launcher constrains the supplied implementation. A future real adapter is absent and must be separately reviewed under D4. Synthetic profiles and result fields carry no real authority.

The module imports only the pinned stdlib reader and stdlib dependencies. A qualification launcher verifies reader and bridge source bytes before loading them. It does not import or execute the inert factory text. `build_real_vad(*args, **kwargs)` raises before inspecting any argument and has no enable switch. Assigning a `REAL_PROFILE` attribute cannot change that function's unconditional refusal or the reader's existing purpose refusal.

| Tensor port method | Required behavior |
| --- | --- |
| `allocate_owned_cpu_f32(shape)` | Return one fresh owner of exact ordinary CPU float32, contiguous strided, zero-offset, detached tensor storage. Each returned tensor owns its complete storage and has no external aliases. If allocation raises before returning a handle, the port must clean every internal allocation itself. |
| `inspect_owned(handle)` | Return exact `TensorFacts`, with true native facts in a future implementation. `storage_start` identifies the start address of the complete owned allocation, and `storage_bytes` its exact size. The bridge checks pairwise non-overlap while all owners remain alive and rechecks identity. Fake addresses are synthetic integers, not observations of native pointers. |
| `copy_owned_f32le(handle, byte_offset, chunk)` | Synchronously copy the exact finite little-endian float32 bits into existing owned storage, preserving signed zero and subnormals. Offsets and lengths are multiples of four; each exact immutable bytes argument is at most 65,536 bytes. Never wrap the immutable chunk or reader snapshot as writable storage. No unsafe deserializer, file loader, inferred dtype, silent cast or shared-buffer fallback is allowed. |
| `read_owned_f32le(handle, byte_offset, byte_count)` | Return a new exact bytes copy of that bounded range, encoded as little-endian F32. Do not return a view. This is a bit-level verification contract; an implementation that returns cached input while native storage differs would violate it. |
| `release_owned(handle)` | Idempotently dispose of this owner. Normal return is the bridge's only release confirmation. A raised exception is counted and success is withheld, but the bridge cannot prove the underlying allocation was freed. The port must tolerate cleanup after any earlier inspection/copy/readback failure. |

The bridge passes a fresh built-in dictionary with the fixed 54 exact string keys to `factory_port.build_strict_owned(state)`. In a future approved adapter, this call invokes the unchanged `build_fixed_candidate_after_release_gates(state)` from the pinned factory, under the required fresh-process/import/global-state conditions. The current fake port merely verifies and copies byte content; it never compiles the factory text.

The factory port owns every model/resource it starts creating. If it raises before returning a product, it must clean partial construction internally; the bridge has no returned owner to release. If it returns successfully, the product must own its state independently of the temporary input tensors. It must not retain aliases that become invalid when the bridge releases those tensors. Native qualification must establish this behavior, including `assign=False`, false swap flags and trusted hooks; naming the method `build_strict_owned` does not establish it.

After successful construction, the bridge first releases all temporary tensor owners and checks its deadline. It transfers the product to the caller only if both succeed. Until transfer, `factory_port.release_product(product)` must dispose of the completed product on failure. A failing product release is also counted; no success is emitted. After transfer, the caller owns the product and is responsible for its eventual release. The frozen `SyntheticResult` is a receipt wrapper, not a capability or an authentication token.

Every returned allocation is placed on the cleanup list before its first inspection. A duplicate handle is already owned and is released once. Distinct handles with overlapping reported intervals are both released. Cleanup runs in reverse allocation order and attempts all known owners even if an earlier release raises. At most 54 tensor releases and one product release occur. The bridge wraps caught failures, including cancellation-like BaseExceptions, into a bounded BridgeRefusal after cleanup; it does not claim to preserve the original exception's class. The original exception is retained as the local cause. A release or native call can block: the deadline is cooperative, not preemptive.

The faithful-port/private-quiescence assumptions remain explicit. Storage addresses, ownership flags and readback bytes are assertions made by the trusted adapter. They cannot protect against an adversarial adapter, concurrent mutation outside that contract or a malicious import graph. The synthetic tests exercise bridge ordering and a concrete bytearray-backed fake implementation only. Real allocation, native readback, full cleanup, imports, factory execution, model values and inference remain unimplemented and unqualified.
