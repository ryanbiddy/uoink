# Documentary seal protocol — 2026-09-13

Root reviews the final preparation hash, `seal.ps1`, `verify_proof.ps1`, source plan and verdict before execution. Only then may `seal.ps1 -ExpectedPreparationSha256 <admitted hash>` run once under the observed PowerShell 7 executable. Neither script invokes Python, a test, a checker, a wheel, a model or the network. Both scripts require exact fixed input structure and fresh output where they write. Keep all partials on failure; no silent replacement or rerun.

The source plan pins 2,266 original paths: every file from the seven named graph roots, 14 standalone records, and the 313 original candidate02 capture files plus their manifest. That is 620,705,901 logical bytes, represented by 532 distinct payloads totaling 127,451,131 bytes. The sealer verifies every source size/hash and full tree membership, then writes each distinct payload once to `payloads.zip`. `SOURCE-PLAN.json` is the exact path-to-ZIP-member map; the archived original manifests retain their original bytes and member names. Deduplication preserves every mapped record, including generated fixtures and failed attempts.

The sealer verifies the current preparation manifests against their current source roots. For the archived 349- and 355-input preparations, it additionally checks that every original expected byte sequence exists in the deduplicated store and records a source witness. It does not pretend the modified current source has an old hash. It checks the declared prior manifest hashes and counts without rewriting them. The separate original313 mapping binds all 313 original capture paths directly.

The scripts refuse links/reparse points in observed paths, unknown source extensions, nonregular or oversized files, path traversal, duplicate logical paths and mismatched content. Source inputs are at most 16 MiB each. Logical input size is bounded to 1 GiB; unique expanded ZIP content to 128 MiB; mapped paths to 3,000; members to 1,000. This is documentary processing in quiescent owned scratch directories, not a race-proof native file authorization system. Path and hash checks may observe source changes; they do not lock every source for the whole task.

ZIP entry names are `sha256/<64 lowercase hex characters>`, sorted ordinally, with the fixed 1980-01-01 timestamp and zero external attributes. Compression is fixed to .NET Optimal in this environment. Different compression implementations need not generate identical compressed bytes; every member's original size/hash must still match. No archive extraction is performed. Duplicate/missing/extra ZIP members are refused. Every member is decompressed only as inert bytes under the per-member and total bounds and hashed independently after the ZIP is closed.

The standalone verifier uses only the proof path, checks the root SHA256 manifest and exact proof membership, then validates every mapped source identity against ZIP content. It does not need the original scratch trees and does not execute or deserialize their code. The root manifest excludes only itself. Reports, maps and verification instruments are ordinary proof payloads. Readable result copies under `readable/` are exact copies of selected already-mapped original records, and their bindings are recorded explicitly.
