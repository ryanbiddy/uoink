# Owned CPU tensor port: source proposal, 2026-09-13

Implement the five tensor methods required by the frozen owned-state bridge. The implementation will use an already imported, trusted Torch module supplied by a future approved launcher. This task writes source only. No module is imported, compiled or executed, and no asset is inspected. The bridge's 61 author and 61 independent synthetic passes do not qualify this new port.

The returned handle must be an ordinary Torch Tensor: the bridge passes it directly into the fixed factory's exact-Tensor check. A private registry will retain each original Tensor and its original untyped storage while ownership is live. Full storage address/length checks and pairwise interval checks run while those references remain held. This prevents reuse of the original allocation during the checks under the trusted allocator and private, quiescent ownership assumptions. It cannot detect every alias created by arbitrary external code.

Allocate CPU float32 storage with explicit device/dtype and no gradients. Copy at most 65,536 bytes per call through a bounded list of Python floats and a fresh CPU float32 staging tensor; copy that tensor into a checked view of the destination. Read back actual tensor values and pack them into fresh little-endian F32 bytes. Never use frombuffer, NumPy, a deserializer, a file loader or a fallback loader. Exact bridge readback must reject changed bits, including signed zero or subnormals. Native conversion accuracy remains unmeasured.

Release retires this port's owning references and attempts to zero only a destination whose original storage identity still matches. A changed identity must never trigger a write to the replacement storage. An allocation that fails before returning a handle is cleaned internally. Normal release return confirms these port operations returned; it does not establish OS memory reclamation, allocator-cache release or absence of references held by the bridge itself. The future factory must own an independent result before temporary tensors are released.

Use a single private port instance for one bridge build: at most 54 successful allocations, 5,891,996 live destination bytes and one 65,536-byte staging tensor. Checks and copies are synchronous and bounded by shape/chunk size; the bridge's cooperative deadline cannot preempt a blocked native call. No concurrency is supported. The D4 launcher must control imports, hooks, thread activity and global state before use; checking TORCH_DEVICE_BACKEND_AUTOLOAD=0 now cannot prove it was set before import.

The application-facing real entry will refuse unconditionally before inspecting arguments. There will be no REAL_PROFILE switch or caller-supplied approval token. The private implementation is concrete proposal code for later review, not an authorized alternate entry. The frozen reader, bridge, factory, existing proofs and production files remain unchanged.

Before any execution, review the exact source and its source-contract table. Later native qualification must verify the currently uncaptured C/native APIs, ownership and alias behavior, every special-value readback, cleanup failures, factory independence, pre-import conditions and the complete controlled runtime. No new fetch or native run is part of this brief.
