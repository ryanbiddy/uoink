# Fixed static-inventory adapter proposal

The pure tracer is sealed separately with 57 passing synthetic cases and an
independent source review. This new scope connects it to the already reviewed
bounded inventory reader. It does not authorize this agent to inspect the
checkpoint. Existing reader, tracer and proof seals remain unchanged.

Use the exact tail reader at SHA256
`67e9edd6c3f6845a8dd3fd21b0b471793b57db0222c56379c0dfce9fcf07c9e5`
and pure tracer at SHA256
`f41ce88a2eceee565fcc9116e19f064723bf3339ffe4ca8669ae20bff6033127`.
Preserve both source files before producing one combined stdlib script.
The only tracer code change is renaming its local `require` helper and
references to `trace_require`, avoiding collision with the reader helper.
Combining definitions avoids dynamic target imports and runtime source
loading in the adapter. Module headers/import placement change mechanically.

Keep the reader's fixed checkpoint path, expected whole-artifact digest,
same-handle hashing, directory/name/extent/member bounds, exact bounded
payload decoding, CRC and final identity checks. Add the tracer result to
the pickle inventory only after the existing literal inventory has completed
on validated in-memory bytes. No new artifact read is needed. Catch
TraceRefusal as refusal exit 2. Check the reader's original cooperative
clock immediately after the symbolic call and again before accepted
completion. The tracer's separate clock cannot reset the reader's overall
30-second budget. Use a fresh scratch receipt directory and
explicit static-symbolic completion/scope labels. Keep the existing 256-KiB
serialized receipt cap; if the combined result exceeds it, preserve refusal
instead of expanding the cap. No output can authorize a loader or model.

The whole-file hash pass reads every artifact byte opaquely, including bytes
belonging to storage members. ZIP directory discovery also scans an opaque
tail window that can overlap storage payload bytes. The adapter must never select, decompress,
extract or interpret a storage member. Only the existing bounded data.pkl
payload is decoded and passed to the tracer. Neither objects, tensors,
reducers, GLOBAL targets nor persistent IDs are resolved or constructed.

The retained reader checks path/handle identity and modification metadata
around inspection and applies the expected digest before ZIP parsing. It
assumes staging is quiescent. It does not provide an immutable filesystem
snapshot against an actor concurrently rewriting the same opened file and
restoring metadata. Do not claim stronger snapshot or provenance guarantees.

Before any actual trace, compare the combined AST against both preserved
inputs with exactly these allowed changes. Synthetic qualification uses
only small in-memory ZIPs and literal pickle bytes, including stored and
deflated success, malformed payload and graph refusal, CRC/size/extent
failure, unchanged hash gate and a wrong-digest inspect path with entirely
inert file/OS fixtures. It also checks unchanged inventory fields and a
refusal that exceeds the output cap.
For receipt/status tests, `main` may run only with its inspection function,
argument parser and every receipt path replaced by inert in-memory fixtures;
that checks return codes without invoking its actual input or output paths.
The original methods and constants are restored after each synthetic case.
The launcher must set the known
forbidden-live string before `-I -S -B`; the child asserts it and installs
artifact/network/native/model audit guards. No actual main/checkpoint run,
product tests, model work, network, tracked edits, staging or commit occur.

Independent source and receipt review must precede any integrator-run
inspection. A cycle, unsupported structure or oversized result in the real
checkpoint remains a documented static refusal. It is not a failed model
trial, and it does not justify widening this grammar automatically.
