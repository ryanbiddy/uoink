## 1. Problem Summary & Defect Diagnosis

Astra observed the installed package-07 dashboard under an isolated profile on 2026-09-12. Creating a note through Sources / "Jot a note" succeeded functionally (persisted text, incremented Library count from 3 to 4, card present), but exhibited display and health defects:

### Defect 1: Inappropriate Media Labeling and Fields
- **Observed Behavior**:
  - The native note card and detail heading displayed `"Saved note video source."` and `"note video"`.
  - The detail view showed video screenshot placeholder (`"Screenshots unavailable. Video screenshots appear here when the source folder includes local frames."`), speaker count/labels (`"Speakers: not labeled yet"`), transcript model checker (`"Transcript checker: Balanced"`), and re-transcription actions (`"Re-transcription: ready"` / `"Re-transcribe"` button).
  - The P4 text-only X fixture similarly displayed `"x video"` despite having `source_type="note"`.
- **Root Cause Analysis**:
  - In `assets/dashboard/index.html`, `mediaLabelFor(row, sidecar)` ignored non-video source types (`"note"`, `"image"`, `"page"`, etc.) and simply formatted `${platform} video` for any platform other than `"youtube"`. For a native note (`platform="note"`), this returned `"note video"`. For the P4 text-only fixture (`platform="x"`, `source_type="note"`), this returned `"x video"`.
  - `renderYoinkDetail()` and `yoinkFactsHtml()` unconditionally rendered video screenshot grids, speaker labels, Whisper checker status, and re-transcription options regardless of whether the source was a plain text note.

### Defect 2: Spurious "NEEDS ATTENTION" on Valid Note Saves
- **Observed Behavior**:
  - The successfully saved note card in Library displayed `"NEEDS ATTENTION"` with description `"Transcript: missing. Screenshots: missing. Comments: missing"`.
- **Root Cause Analysis**:
  - In `server.py`, `compute_health(sidecar)` computed health strictly as a video extraction health snapshot. It checked `sidecar.get("transcript")`, `sidecar.get("screenshots")`, and `sidecar.get("comments")`.
  - In `notes.py`, `persist_note()` persists notes with `"note": md` (not `"transcript"`), and does not write video screenshots or comments.
  - When `server.py`'s `_enrich_yoink_rows()` loaded the note sidecar on `/memory/search` or `/recent`, `compute_health(live)` evaluated all three fields as `"missing"`.
  - In `assets/dashboard/index.html`, `healthException()` flagged these missing media assets as failures, incorrectly marking the clean note save with `"Needs attention"`.
  - Screenshots and comments are inapplicable to notes. For notes, text body existence represents health; absent inapplicable assets must not produce failure states.

### Defect 3: Misleading Loading State in Local Facts
- **Observed Behavior**:
  - In the note detail view, even after the note markdown text was loaded and file status read `"ready"`, the Local facts section displayed `"checking saved files"` and `"Saved details: saved details need another moment"`.
- **Root Cause Analysis**:
  - In `assets/dashboard/index.html`, `openYoinkDetail(row)` initiates `loadJsonFile(sidecarPath)`, which requests `GET /file?path=${encodeURIComponent(sidecarPath)}`.
  - In `server.py`, `/file` is an authenticated image-only endpoint (`_resolve_served_file()` restricts MIME types to `_SERVED_IMAGE_TYPES`: `.png`, `.jpg`, `.jpeg`, `.webp`).
  - Serving `.json` files via `/file` returns HTTP 415 `"unsupported file type"` (and for fixtures outside output root, HTTP 403 `"path escapes Uoink root"`).
  - The `.catch()` block in `openYoinkDetail()` caught this rejection and set `state.selectedYoinkSidecarError = "saved details need another moment"`. Because `state.selectedYoinkSidecar` remained null, `els.yoinkFactMeta.textContent` stayed `"checking saved files"`.
  - For notes, all metadata is self-contained on the row and in the note markdown; no external media sidecar fetch is needed. Omitted sidecar data for notes was causing a permanent fake loading state.

## 2. Implementation Plan

1. **`server.py` (`compute_health`)**:
   - Detect note source types (`source_type == "note"` or `platform == "note"`).
   - For notes:
     - Check note body content (`sidecar.get("note")`, `text`, `markdown`, or `transcript`). If non-empty, report `"transcript": "ok"`; if absent, report `"missing"`.
     - Mark inapplicable media assets (`screenshots`, `comments`) as `"skipped"`.
     - Keep hook and comment intelligence as `"skipped"` (or existing status).
   - Preserve exact video, podcast, live, and image behavior.

2. **`notes.py` (`persist_note`)**:
   - Populate health snapshot on the persisted sidecar and row metadata (`health_score_json`) consistent with `compute_health`.
   - Ensure note persistence remains standalone without importing `server.py`.

3. **`assets/dashboard/index.html`**:
   - Update `mediaLabelFor(row, sidecar)` to recognize canonical non-video source types (`note`, `image`, `page`, `x_article`, `x_thread`, `reddit_thread`). Return `"note"` for notes (repairing both native notes and the P4 text-only X fixture).
   - Add helper `isNoteContent(row, sidecar)` to identify note uoinks.
   - In `renderYoinkDetail()`:
     - For notes, omit the screenshot grid (`mediaBody = ""`), so video screenshot placeholder is not shown.
     - For notes, disable `els.yoinkRetranscribe` with appropriate tooltip.
     - Update section heading to reflect note content (`"Note"` instead of `"Transcript preview"`, `"saved note"` instead of `"0 segments"`).
     - In Local facts meta, display `"ready"` when note row is selected.
   - In `yoinkFactsHtml()`:
     - Omit video/audio specific facts for notes (`Duration`, `Speakers`, `Transcript checker`, `Re-transcription`).
     - Label note file as `"Note file"`.
     - Report `"Saved details": "ready"` for notes without attempting invalid sidecar fetching.
   - In `openYoinkDetail()`:
     - Avoid executing `loadJsonFile` on note sidecars since notes do not depend on media sidecar data.

4. **Regressions & Constraints**:
   - Keep file path containment and `/file` 403/415 refusals intact (no weakening, no fetch added).
   - Add focused regressions verifying note display labels, facts, health computation, and Node-rendered dashboard UI.
