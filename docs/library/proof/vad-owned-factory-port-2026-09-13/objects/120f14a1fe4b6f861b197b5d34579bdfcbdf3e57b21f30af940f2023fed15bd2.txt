# Worker-local model capability and lifecycle

The concrete registry implements assert_active and assert_vad_model_binding, the methods used by the preserved owned guard. Its source is separate from real bootstrap admission. open_real_model_registry and open_real_factory_port refuse unconditionally. No registry or factory is installed into the actual owned runtime here.

The private bootstrap creates one worker-local registry with an exact object permit and a new generation identity. Only that same permit can issue one capability for one exact factory instance and close the generation. A string, serialized record, public model class or caller profile cannot replace the permit. The capability is recorded by object identity in the registry; directly constructing a capability object cannot make it a registered capability.

The bootstrap must independently verify the input snapshot/output recipe before issuing its passive _StateBindingProposal: output SHA-256, approved profile-binding SHA-256 and the ordered 54 key/shape/value-digest associations. The dataclass itself carries no authority. This source validates its shape and identity-bound issuance but does not implement the real snapshot trust gate or authenticate the contents of the supplied hashes. The state binding retains no snapshot or input Tensor references.

The factory receives the capability through a private post-construction binding step. It checks exact factory identity and that the owned runtime module's _RUNTIME is this registry. After schema/value/storage verification, it supplies the 54 observed input value digests; registration requires an exact match to the capability's state binding and the fixed model type. The returned lease strongly holds the exact model. The preserved VoiceActivitySegmentation constructor then calls its real owned guard, which can find only that exact active object in this generation.

The lease stays active through VAD construction, instantiate and successful use. Final ownership publication is checked while holding the registry lock; the body performs only Python ownership assignments. A close that wins first prevents publication. If publication wins first, a result may reach its worker-local caller after later revocation; subsequent bound-use checks must reject the revoked lease. The constructor's check alone cannot prevent arbitrary trusted code from directly invoking a retained raw object. Raw model/VAD/generator objects must never cross the controller facade.

Failure or release revokes the capability and lease before owners are cleared. Generation revocation marks the entire registry inactive before clearing model/factory references. References that might trigger native destruction are retained until after the state lock is released. A failure to confirm revocation preserves the factory's owner record and reports model_revocation_unconfirmed; native bootstrap must quarantine that worker/session. Normal local revocation is not process quiescence or native shutdown evidence.

Coordination with the current controller proposal is explicit. `_scratch/asr-windows-lifecycle-proposal01/snapshot_lifecycle.py` binds an exact live OwnedSession and record.permit object locally, then revokes before close/join and requires independent quiescence confirmation. Its author confirmed there is no concrete worker-generation or IPC authority to reuse yet. Copying or serializing that controller permit cannot preserve object-identity authority in another process. A future trusted bootstrap and authenticated, bounded IPC handshake must bind this worker-local generation to that exact controller session/permit and revoke it before worker shutdown. That connection remains unimplemented, and the current controller proposal is independently unqualified.

The preserved guards are `_uoink_owned.py` SHA-256 7672f614d81cf0be5e7bd408f8f856af328fe34e6ca7ee707c9d0db838e56d1f and vads/pyannote.py SHA-256 aeec3ec09d1ed7e11f827353c4f9087de665b1cd3dabf3ff47bb5917c679c6f2 under `_scratch/whisperx-owned-builder-proposal01/inputs/after/whisperx`. They remain unchanged. The registry currently provides the factory's active/model-binding subset; ASR snapshot, waveform, media and operation methods remain other owned-runtime integration work. No test may pretend that the missing full runtime or real IPC is already implemented.
