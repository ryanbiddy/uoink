# Owned fixed-factory port: source proposal, 2026-09-13

Implement the bridge's build_strict_owned and release_product methods as a concrete transaction around the reviewed fixed PyanNet/VAD construction. This is source only: no import, compilation, model construction, asset inspection or test execution is authorized. The earlier bridge and CPU-port fake results do not qualify this new factory port.

Use an already imported, exact-source-bound fixed-factory module and the already bound CPU tensor port as trusted implementation dependencies. Artifact content cannot select classes, callbacks, modules or profiles. The public real entry refuses unconditionally. Do not change the frozen factory text, fixed configuration, recorded-versus-proposed values, reader gates or bridge source.

The transaction will copy the fixed factory's constructor/load/VAD steps into inspectable method bodies, registering the returned model before build/load and the returned VAD before instantiate. It will preserve the same PyanNet arguments, Specifications bridge choices, strict=True/assign=False load and VAD thresholds. Exact ordinary input keys/shapes and current no-swap/import settings remain required. Bound model state checks to the fixed 54 entries.

Before returning a product, compare every model-state tensor's logical values to the owned input through bounded F32 readback and reject overlap between any model storage and any live input storage. Retain the original model storage references through the transaction. This checks the result's parameter/buffer independence under the trusted native storage contract; it does not prove that every reachable Python attribute is free of aliases.

Every model/VAD object returned by its constructor becomes the transaction's responsibility immediately. If a constructor raises before returning an object, its implementation must clean its internal construction; the port cannot retire an owner it never received. On a later failure, drop all transaction-held references, including state views and storage pins, before propagating the failure. Python tracebacks, caller references and native caches can still retain objects. Release normal return means this port retired its ownership; it does not establish OS reclamation, destruction of a caller-held product or a successful native shutdown. Preserve this limit instead of inventing a close API absent from the captured source.

Use one private factory port for one build. A successful VAD remains owned by the port until bridge cleanup completes and the caller receives it; on bridge failure release_product retires that result. Caller disposal after successful transfer can use the same method. No input tensors or snapshots may be retained in the port's completed-product record. The future native qualification must verify strict-load values, independent storage, product behavior after input zeroing, constructor/failure lifetimes, controlled hooks and native imports before this becomes an application route.
