### Review of Bounded Repair

#### Root Cause Analysis
During reader operation cleanup in [`library_resources.LibraryReader._disarm_sqlite_deadline`](file:///C:/Users/hello/AppData/Local/AgentControlRoom/worktrees/uoink-library/c52710a3-21e/gemini/library_resources.py#L1216-L1239), the disarm routine invoked:
```python
conn.set_progress_handler(None)
```
In Python's `sqlite3` module (CPython `_sqlite3`), `set_progress_handler` requires two arguments `(progress_handler, n)`. Calling it with a single argument raises `TypeError: set_progress_handler() missing required argument 'n' (pos 2)`. Because the call was wrapped in:
```python
except (AttributeError, sqlite3.Error, TypeError):
    pass
```
this `TypeError` was silently suppressed, leaving the armed deadline progress callback attached to the shared SQLite connection. When a subsequent operation (such as Phase 6 `export_cited_range`) executed queries on that same connection after the reader's former deadline had elapsed (e.g. 2.1 seconds later), the lingering `progress` handler returned `1`, causing SQLite to raise `SQLITE_INTERRUPT (9)` (`sqlite3.OperationalError: interrupted`), which mapped to `library_unavailable` with `details.reason: storage_error`.

#### Product Fix
In [`library_resources.py`](file:///C:/Users/hello/AppData/Local/AgentControlRoom/worktrees/uoink-library/c52710a3-21e/gemini/library_resources.py#L1228), the disarm call was updated to the supported callback-removal signature:
```python
conn.set_progress_handler(None, 0)
```
This cleanly removes the callback from the SQLite connection without raising `TypeError`, ensuring that both normal and exceptional reader completions disarm the deadline handler.
