## Repair recorded before rerun

Helper authority now uses the original Thread object; the integer ID remains
diagnostic metadata. Python explicitly permits integer IDs to be recycled
([threading reference](https://docs.python.org/3/library/threading.html#threading.get_ident)).
Existing operation context and originating-helper controls remain intact.

Prepared-only cancellation clears pending launch and releases after proven
absence of a child. Launch rechecks cancellation under the same state lock.
The in-progress handoff stays owned through job assignment, including after
Popen returns its process object. Cancellation during that handoff returns
without closing the launcher's job. State locks do not span Popen or pipe
reads. Later child-job assignment checks cancellation under the state lock.

A nonblocking termination lock gives native-job cleanup one owner. Concurrent
cancel requests mark admission dead and return false while that owner finishes.
Graceful shutdown delegates final cleanup to the same path. The redundant
second job close on the Popen exception path is removed. This prevents the
same ownership problem from moving to overlapping termination calls.
