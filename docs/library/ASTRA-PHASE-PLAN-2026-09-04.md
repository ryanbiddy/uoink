**Phase 2: a reversible Librarian that can wait for a client**

Scope: versioned taxonomy proposals, assignment staging, a leased work queue, validation, previews, apply/undo, user pins, and recovery. Start with assignment against an explicitly approved fixed taxonomy. Add induction and concept revisions after assignment and recovery work. Defer automatic structural triggers until their false-positive and churn behavior is measured. The current schema and tool names are a starting point, not a ready-to-copy implementation (`WORK-QUEUE-CONTRACT-2026-09-04.md:61`).

Proposed ownership: Astra owns the state-machine specification, migration and transaction implementation, because retry and recovery semantics must stay under one owner. Claude owns thin server/registry adapters and the review UI after that interface is frozen. Gemini owns independent fixtures, label adjudication and quality evaluation. Grok reviews the measurement report and rate assumptions. Fable owns integration and the final combined verification. Model names are staffing choices based on this run's context, not claims that only one engine can perform a task.

Files: a new `library_work.py` service, shared `library_cards.py`, the reserved substrate migration, narrowly scoped `index.py` helpers, `uoink_mcp_tools.py`, `server.py`, `assets/dashboard/index.html`, client instructions, and tests covering state transitions and recovery. Extend the existing export/rebuild path rather than creating an optional vault dependency for user corrections (`index.py:788`, `memory_layer.py:288`).

Freeze these semantics before dispatch:

- Use one work row per item for assignment; a lease response may contain a batch. Induction is one separately bounded sample task. This removes the draft's ambiguity between multiple work rows and multiple cards in each payload (`WORK-QUEUE-CONTRACT-2026-09-04.md:276`).
- Claim in one transaction. Issue a random attempt token distinct from client ID and work ID. Increment attempts only on claim; expire/renew/cancel explicitly. Every submit carries the attempt token, schema version, item revision and taxonomy revision. Reject stale or mismatched submissions. A repeated identical completed submission returns its recorded response; changed content under the same key is an error.
- Validate result identity, cardinality, finite confidence, allowed shelf paths, evidence kind and quote provenance in the service shared by all adapters. Submission stores accepted and rejected results without changing current assignments. Rejected or omitted items remain visible and retryable; they must not disappear into a successful batch count.
- Give shelves stable identities with versioned names/definitions. Keep proposed assignments separate from active assignments. Activation requires a completed target manifest, with pinned, deleted, unsupported, and changed items explicitly accounted for. A source revision change invalidates its old pending result.
- Apply against an expected projection revision and an operation key. Preview returns the exact proposed delta and its hash; apply rejects a changed delta. The journal records forward and inverse operations for additions, replacements, deletions, activation and pins. Repeating apply is a no-op with the same receipt. Stale undo returns a conflict; it never overwrites a newer pin.
- Define pins as user-owned decisions, including whether an explicit move permits other unpinned memberships. A taxonomy rename must not silently orphan a pinned identity. Persist a local authoritative correction record before acknowledging the pin as durable; use operation IDs and replay to recover from a crash between filesystem persistence and database projection. Optional Obsidian mirroring cannot satisfy this contract.
- Compute churn over distinct affected items with a documented baseline and empty-library rule. The adopted 15% threshold remains a provisional review stop, not a quality metric. Initial filing is reported separately. Enforce ceilings in the service rather than accepting arbitrary model-supplied overrides.

Delivery gates: concurrent claims grant one current lease; expired attempts cannot submit; duplicate submit/apply does not duplicate work; changed input invalidates results; rejected output writes no labels; locks survive every transition; undo restores the exact prior projection; crash/restart and reconstruction from authoritative files preserve pins. Test these on disposable databases with forced interruption between durable steps.

The product proof is a dry run across the frozen copy using the agreed card profile, with no applied labels. Report every item's accepted/rejected/unmapped outcome and its evidence. Measure real request/response usage when available, exact serialized input size, retries, failures and end-to-end wall time. If a subscription client omits token usage, mark it unavailable; it cannot establish a dollar-cost gate. Freeze the human-adjudicated evaluation split and acceptance thresholds before running the model. A proposed target is primary-shelf precision of at least 0.90 on that held-out set, reported separately for clip-bearing and metadata-only items; it is a target, not a result or a reason to hide abstentions. Apply remains disabled until the preview, independent evaluation and recovery gates pass. The UI must show waiting-for-client status when no worker runs.

The early repair increment provides hardened Recall and clip reads. The remaining scope is bounded resource reads/templates, user-invoked prompts, generated briefs, client installation/configuration, and an opt-in corpus mirror. Support one concrete client/transport pair end to end before multiplying connectors. Do not put a local helper on a public tunnel merely to satisfy a cloud scheduler's reachability requirement.

Claude owns common transport adapters and client configuration. Astra owns browser/client acceptance and the resource contract review. Gemini tests malformed requests, untrusted text and deletion behavior. Fable owns integration. Files: `uoink_mcp.py`, `server.py`, shared resource rendering module, `memory_layer.py`, `skills/uoink/SKILL.md`, client configuration docs, `.mcpb` assets, and a proposed registry manifest if its distribution gate is met.

The resource URI must include stable item identity plus source/selection revision or a stable excerpt key. A sequence number alone can point to different text after re-extraction (`clips.py:255`). Advertise only capabilities that both routing and notification behavior implement. Keep old clients operational while testing an SDK migration. The official 2026-07-28 release already includes Python support; use its migration path as the starting point rather than assume an SDK rewrite is necessary. [MCP release](https://blog.modelcontextprotocol.io/posts/2026-07-28/).

Mirror gates include sanitized deterministic paths, collisions, user-edited generated files, atomic writes, stale output, tombstones, hard deletion and disconnected vaults. Keep the authoritative correction store separate. Avoid letting a generated mirror silently expand corpus egress through another indexing tool. Gates for each supported client: discover the intended read tools, retrieve the same item/quote/revision, follow a real link, survive a helper restart, and report a bounded failure when unavailable. Resource and hook quotations must pass the same trust-boundary tests. OAuth/cloud connectors are separate scope if a specific client requires them.
