# Installed chapter scenario: instrument review

The separate scenario is approved for the package-07 isolated installation.
It creates one visibly synthetic item and publishes its stored cue and chapter
through the installed server._publish_capture_media producer. Publication uses
the existing build-time ticket and revision checks. The original P4 fixtures,
their incomplete chapter sidecars and their failed observations stay unchanged.

The outer observer checks the package seal, frozen source bindings and installed
files before starting. It installs the existing automatic interpreter guard,
proves the guard with an owned canary and launches the scenario in an owned job.
It restores the guard and interpreter path file only after child cleanup is
affirmed. Read observations compare the isolated database, item artifacts,
settings, sentinel and four frozen client configuration files before and after.
Preparation may create these separate synthetic files; reads may not change them.

The first observation uses the original installed stdio entry point. It lists
resources, waits more than two measured seconds on the same process and exports
the cue-aligned range. The response must match the publication result exactly,
including stored text, overlapping chapter and current revisions. Speaker labels
and inference claims are absent. This synthetic source has no supported player
seek; both seek fields must remain null. Raw frames and process outcomes are kept.

The actual-client stage references the already authenticated isolated
Claude namespace without copying credentials. It rechecks subscription auth and
uses Ryan's retained confirmation that extra paid usage is off. Strict client
configuration exposes the existing bounded reads and export_cited_range; all
capture and write tools are denied, and shell/browser built-ins are unavailable.
The inert sentinel remains an observation surface with no effects. Separate
synthetic hook probes check export permission and capture/shell denial before
any model is launched. They are not counted as actual client tool calls.

Astra checked the current APIs before execution: the text field is
citation.verbatim_text, attribution labels use attribution.labels, and successful
stdio tool text uses the product's fenced rendering. Python syntax checks pass.
These are pre-execution instrument corrections, not changes to measured results
or acceptance assertions. No scenario has passed merely because this review or
a process exit is successful. Actual results and timing must be reviewed after
execution; any failure needs a diagnosis and a brief before another attempt.

This headless scenario supplies no GUI click or external-player screenshot.
Same-account isolation is not a separate Windows account or an ordinary upgrade.
