## Rulings on the seven BC-1 header entries

1. **Stale concurrent publisher: reject the waiver; fix before acceptance.**
   `publish_transcript` uses previously recorded run IDs and a changed cue hash
   as its supersession test. Neither proves publication ownership. Offline
   probes published A, then B, then A again: old snapshots overwrote B with
   diarization off, with source-provided labels, and with an annotation-only
   change that kept the same cues. A first attempt with an unseen run ID also
   falls outside the check by inspection.

   BC-2 must enforce publication ownership independently of diarization. The
   owning service needs a generation or expected-base fence, checked under the
   shared capture/item lock before file replacement and held through settlement.
   Recheck deletion, corpus bytes and sidecar dependencies there. An old publisher
   must refuse `revision_unavailable` before touching files; a retry of the same
   still-authorized publication must recover from each file/DB boundary. An
   internal service wrapper may carry this state without changing media hashes
   or public export inputs. The raw helper must not offer an unfenced bypass.
   `BEGIN IMMEDIATE` serializes SQLite writers; it does not establish capture
   ownership or protect files from other feature owners.

2. **Phase 2 invalidation: permit a low-level raw-connection helper, reject an
   incomplete publication path.** The owning Index/service operation must commit
   a coherent source/citation/media/clip snapshot and invoke the existing Phase 2
   invalidation service. Callers cannot rely on a docstring reminder. Preserve
   the shared card algorithm and its decision about whether source inputs changed;
   a media revision is not a replacement source revision.

   `Index.store_media_snapshot` commits without invalidation. In
   `podcasts.episode_to_corpus`, `upsert_yoink`, `insert_citations` and
   `store_media_snapshot` commit separately; invalidation from the first two
   does not prove invalidation after a coherent final publication. The citation
   method also returns early on an empty list and logs clip-build SQL errors
   before committing. BC-2 must route production publication and reconstruction
   through a complete operation, cover empty/shorter replacements, and propagate
   projection/invalidation failure with a recoverable state. Verify with existing
   Phase 2 work, not just an empty library or an invalidation-call spy.

3. **Artifact retention: reject indefinite retention of unreferenced inputs.**
   Retain the union needed by the current sidecar and retained run ledger, plus
   inputs still needed to settle an authorized interrupted publication. A changed
   transcript with no run ledger left its old `.media-inputs/<hash>.json` behind
   in an offline probe. Item deletion alone does not satisfy the contract's
   retention rule while that item remains active.

   BC-2 must prune obsolete owned inputs after successful settlement, under the
   same ownership rules, and make interrupted cleanup retryable. Preserve current
   inputs, retained-run artifacts, original capture files and other owners' files.
   Reads must not perform cleanup. Test both an obsolete source/caption artifact
   and an old artifact still required by a retained run; verify hard purge too.

4. **No production `media_fragment` seek: accept the capability restriction.**
   The contract grants this kind only to an implemented, tested player path.
   Podcast publication's `seek_kind="none"`, null seek URL and null exported
   player command are correct until that path exists. Keep the original safe
   source citation; an episode-page fragment does not establish playable media.
   Fixture arithmetic proves neither a production player nor audible alignment.
   BC-2 must verify null production seek fields. Any later seek claim needs its
   actual player path tested; unavailable seeks stay unavailable in BD's metrics.

5. **Export implemented in BC-1: accept the scheduling change, keep all gates.**
   The domain operation can support BC-1's tests. It does not complete BC-2.
   Registry/stdio exposure, exact input rejection before storage access, common
   admission, final transport budgets and untrusted-data rendering still need
   adapter-level tests. Export must remain a read; it creates no new Phase 2
   evidence basis, acquisition permission or save action. The export defects
   listed below must be fixed before adapters advertise completion.

6. **`unsupported` with `not_materialized`: accept for unmaterialized text-only
   items.** The contract's specific virtual-view paragraph resolves the general
   table wording: text-only items have empty cues and unsupported annotation
   states; `not_materialized` explains why the view has no stored media snapshot.
   Legacy timed items use absent annotations with that reason. Both return a
   deterministic virtual media hash and write nothing. A materialized unsupported
   adapter uses its recorded reason, normally `adapter_unsupported`.

   `_virtual_block` currently selects unsupported solely when the cue list is
   empty. That shortcut is broader than the text-only exception; an empty or
   failed timed capture is not automatically a prose item. BC-2 must preserve
   source/evidence classification and test both cases, without promoting discovery
   hints into text evidence.

7. **Sidecar link fields: accept exact legacy recovery, reject contradictory
   explicit fields being ignored.** For a legacy row missing fields, trying a
   recorded convention is permissible only when the recovered cue revision and
   every cue hash match exactly. Never reseal hashes or choose a nearest match.
   New writers must persist actual stored link values, including nulls and the
   compatibility `youtube_deep_link` value. Preserve numeric representations
   needed for the original cue binding.

   `_cues_from_sidecar` tries legacy modes after an explicit-field mismatch. A
   probe changed every explicit source URL and deep link; the helper silently
   recovered the old links anyway. `server._citations_from_sidecar` uses `or`
   for the two source fields, replacing explicit nulls with generated links.
   Both must be fixed. Only missing fields qualify for legacy recovery; explicit
   mismatches refuse `invalid_source_data`. Preserve unrelated sidecar keys and
   the original compatibility-column convention. A generic podcast link must
   not acquire YouTube playback meaning through that column.

## Further BC-2 requirements from inspection

- **Validate original artifacts on export.** `_read_snapshot` checks referenced
  paths with `is_file()` but does not verify their bytes. Replacing a referenced
  JSON artifact with corrupt non-JSON bytes still returned a successful range in
  an offline probe. Missing inputs must return `library_unavailable`; corrupt
  bytes/bindings must return `invalid_source_data`. Apply bounded digest, JSON
  and producer/locator validation, including the contract's source-record match,
  through the shared validator. A hash-shaped descriptor is not source evidence.
- **Make the read coherent and bounded.** `_read_snapshot` performs separate
  SELECTs without establishing a read transaction; `_export` performs no final
  source/media recheck. BC-2 must cover concurrent source/media replacement and
  deletion, files changing during a read, and lock waits within the shared
  two-second deadline. Adapter locking must not turn the deadline into an
  unbounded wait. Verify actual wrapped response sizes and refusal versions;
  do not add a second independent admission pool.
- **Finish production paths.** In the inspected files, `chapters_from_metadata`
  has no call site in the helper's capture path, and `server.py` has no call to
  the shared media publisher, snapshot builder or renderer. Podcast publication
  builds a media block but still uses its older renderer and the separate commits
  described above. BC-2/integration must connect already-held chapter metadata,
  final Markdown, sidecar and DB publication through the common validation path.
  `clips.build_clips_for_video` also catches `MediaError` and replaces clips with
  unannotated rows; that is not the required refusal preserving an existing
  materialized snapshot. Test the real writer/reconstruction seams with supplied
  data and stubbed execution, including projection failure and sidecar conflicts.
- **Update inventories against this integrated baseline.** Static AST inspection
  finds 87 registry tools, 31 decorated stdio tools and 31 manifest entries;
  `export_cited_range` is absent. The two Phase 4 brief tools are already present.
  The BC brief's 86/30 target is stale: one additive export yields **88/32** here.
  Preserve the existing names and update `uoink_mcp_tools.py`, `uoink_mcp.py`,
  `tests/test_c01_mcp_stdio.py`, `tests/test_phase4_stdio.py`, `.mcpb/manifest.json`,
  `docs/v2-mcp.md`, `docs/v2-api.md`, `tests/test_phase0_registry_capture.py` and
  `tests/test_docs_live_contracts.py` together. Derive totals from the final
  candidate if another tool lands first. Keep existing resources/prompts intact.
