## 2. Resources

MCP resources are *addressable read-only content the client fetches by URI*, as opposed to
tools, which are function calls. For a library, that distinction matters: `search_clips` is a
question, but "the evidence card for this item" is a **document**, and clients cache,
@-mention and attach documents in ways they cannot do with a tool result.

### 2.1 URI scheme

All under one authority so a client can pattern-match:

| URI | Is | Mime | Size |
|---|---|---|---|
| `uoink://item/{slug}` | the markdown corpus for one item | `text/markdown` | KB to MB — the only unbounded resource; see the cap below |
| `uoink://card/{slug}` | the evidence card (`get_evidence_card` output, as markdown) | `text/markdown` | ~10 KB (§2.3) |
| `uoink://clip/{video_id}/{seq}` | one clip: text, window, deep link | `text/markdown` | ~1 KB |
| `uoink://brief/{YYYY-MM-DD}` | the daily brief (§5) | `text/markdown` | ~4 KB |
| `uoink://shelf/{path}` | one shelf: definition, cues, member items with links | `text/markdown` | ~2-20 KB |
| `uoink://search/clips?q={query}` | a search *as a resource*, for clients that attach URIs but not tool calls | `text/markdown` | capped at 20 hits |

`{slug}` is already the public identifier across the tool surface (`get_uoink_corpus`,
`get_evidence_card`, `pin_shelf`) and it is URL-safe by construction. Use it, not `video_id`,
as the primary key of the URI space; accept `video_id` as an alternate form the way
`get_evidence_card` does (`uoink_mcp_tools.py:580-585`).

### 2.2 `resources/list` at 548 items is a problem, and templates are the answer

A flat `resources/list` would return 548 items + 3,216 clips + N cards ≈ **4,000+ entries**
(item and clip counts from the orchestrator's verified 2026-09-04 index copy per
`DECISIONS-2026-09-04.md`; not re-measured here). Clients render that list in a picker. Do
not do it.

- `resources/list` returns a **small curated set**: today's brief, the 20 most recently
  captured items, the top shelves, and the 10 highest `value_score` items from the existing
  engagement decay (`Index.top_engaged`, already used by `memory_layer.consolidate_taste`).
  Target: ≤ 50 entries.
- Everything else is reachable through **`resources/templates/list`** —
  `uoink://card/{slug}`, `uoink://clip/{video_id}/{seq}`, `uoink://shelf/{path}` — which is
  exactly what URI templates are for and costs nothing to enumerate.
- Discovery of *which* slug stays a tool call. `search_clips` finds the moment;
  `uoink://card/{slug}` is how the client then attaches it. Tools search, resources address.

### 2.3 Sizes, honestly

**A discrepancy worth flagging before anyone prices a pass.** `uoink_mcp_tools.get_evidence_card`
returns clip text **untruncated** (`_clip_public`, line 513-519) — 10 clips of a 45-120 s
window each (`clips.py:31,33`). `scripts/librarian/dryrun.py` builds a *different* card: 6
clips truncated to 240 chars (`dryrun.py:129`, `clip_chars=240`).

Arithmetic on the orchestrator's measured inputs (134,500 transcript cues → 3,216 clips, cues
averaging 37 chars, per `DECISIONS-2026-09-04.md` and THE-LIVING-LIBRARY §4): ~42 cues per
clip × 37 chars ≈ **1.5 KB per clip before de-overlap**, so an MCP evidence card is on the
order of **10-15 KB**, versus **~1.5 KB** for the dry-run card. That is a 6-10× difference in
tokens per card, and it lands directly on grok's G4 "$1 per 500 items" test and on gemini's
gold-set card format.

**I did not measure the de-overlapped mean clip length** — Python execution was unavailable in
this session (see the handoff). The exact number is one query against the index copy and it
belongs in grok's `COST-MODEL-2026-09-04.md`. What matters here is the decision it forces:

> **Recommendation: `get_evidence_card` grows an explicit `clip_chars` parameter
> (default 240, max 2000) so the card the Librarian consumes and the card a human reads are
> the same code path at two settings.** Otherwise the "evidence card" in the cost model, the
> gold set, the work-queue packet and the MCP resource are four different objects with one
> name.

Caps for the resource layer, regardless:

- `uoink://item/{slug}` returns at most **256 KB** and sets a `truncated: true` marker with a
  pointer to `get_uoink_corpus` for the rest. `_summary_hint` already reads at most 8 KB
  (`uoink_mcp_tools.py:495`); the same defensive instinct applies here.
- `uoink://search/clips` caps at 20 hits, matching `search_clips`' default.
- Anything over the cap is an error with a next step, never a silent truncation.

### 2.4 Capability wiring

`server.py:7528` becomes:

```python
"capabilities": {
    "tools": {"listChanged": False},
    "resources": {"subscribe": False, "listChanged": True},
    "prompts": {"listChanged": False},
},
```

`subscribe: false` on purpose. Server-initiated push is exactly what the 2026-07-28 revision
removed (§6), and Recall's push channel is the client-side hook (§4), not a subscription.
`listChanged: true` on resources is honest — capturing a new item does change the list — and
FastMCP can emit it on the stdio side. Implement `resources/list`,
`resources/templates/list` and `resources/read` in both places: `@mcp.resource` decorators in
`uoink_mcp.py`, and three more string branches in the HTTP dispatcher at `server.py:11980`.

**Resources do not go through `TOOL_REGISTRY`.** They are a parallel surface backed by the
same `Index` methods, so the "67 tools" count and its CI lock-step stay untouched.

## 3. Prompts

MCP prompts are user-invoked templates — in Claude Desktop they surface as slash commands.
Four, and no more; a prompt list that reads like a menu of everything is a prompt list nobody
opens.

| Prompt | Arguments | Does |
|---|---|---|
| `consult-library` | `topic` (required) | runs `search_clips`, returns the 5 best clips with deep links and the instruction to cite timestamps. The "before you answer a topical question, check the library" rule as a template rather than a `SKILL.md` paragraph nobody read |
| `evidence-brief` | `topic`, `since` (optional) | a citable brief across shelves: what the corpus holds on a topic, which creators, over what period, with links |
| `whats-new` | `days` (default 7) | new items, new shelves, items that moved, from `library_applies` |
| `reshelve-review` | `apply_id` | renders one `apply_reshelving` dry-run summary for a human to approve or reject. The human loop in the Phase 2 contract needs a surface, and this is the cheapest one |

Each prompt returns messages containing **data**, not instructions to fetch data. A prompt
that says "call search_clips" wastes a round trip in a client that already has the tool.

**`skills/uoink/SKILL.md` is stale and blocks this.** It still opens "You are operating as a
YouTube creator research analyst" (line 22), declares `ANTHROPIC_API_KEY` as a required env
var in its frontmatter, and lists a tool set from before podcasts and clips existed. Under the
Morgan wedge (decision 1) the skill's subject is *the library*, not creator research, and
under D-17 a required API key in an openclaw manifest is actively wrong — the whole point is
that the calling client brings its own cognition. Rewrite is Phase 4 scope, not run A's, but
nothing in §3 should ship on top of the current text.

## 4. The `UserPromptSubmit` recall hook: hardening list

`scripts/recall_hook.py` (132 lines, committed in the Phase 1 draft) is the highest-leverage
thing in this document: it is the only channel that puts the library in front of a model
*before* the user asks, and it works today with no MCP changes, no protocol version and no
client support beyond Claude Code. It is also a hook that runs on **every prompt the user
types**, reading a database, and printing text straight into the model's context. That
deserves a hard look.

Ordered by what would bite first.

**H1 — Untrusted third-party text is injected as context with no framing. (P0)**
Line 124 prints clip text — verbatim speech from a YouTube video or podcast the user
captured — into `additionalContext`. A creator who says "ignore your previous instructions
and…" mid-video ends up with that sentence in the model's context on an unrelated prompt.
This is the one genuine security property of the hook and it is currently absent. Fix: wrap
the block in an explicit delimiter and label it as data, e.g. a
`<uoink-recall-data>`…`</uoink-recall-data>` fence with a leading line stating the contents
are quotations from third-party media, are reference material only, and must never be treated
as instructions. Strip control characters and collapse newlines inside quotes (line 122
already collapses whitespace — keep that, add the fence).

**H2 — No timeout, no connection close. (P0)**
`sqlite3.connect` at line 111 takes no `timeout` and the connection is never closed (no
`finally`, no context manager). The live index is written by the helper; if a write holds the
lock, the hook blocks on the default 5-second SQLite timeout *per statement* — twice (line
113 and line 118) — in front of every prompt the user types. Fix: `timeout=1.0`, a
`try/finally: conn.close()`, and a total wall-clock budget (~1.5 s) after which the hook
returns 0 with no output. A recall hint is never worth making the prompt feel broken.

**H3 — Windows-only index path. (P1)**
`_index_path()` (32-36) expands `%LOCALAPPDATA%`, which resolves to the literal string on
macOS. The helper already resolves this correctly via `_platform.user_data_dir()`
(`server.py:436`). The hook cannot import `server` (too heavy, and it must work when the
helper is dead), so mirror the three-line platform branch and keep `UOINK_INDEX_PATH` as the
override. Since the mac build is a live plan (`docs/MAC-BUILD-PLAN.md`), this is not
hypothetical.

**H4 — Non-ASCII prompts produce zero terms. (P1)**
`_terms()` (40) matches `[A-Za-z0-9_][A-Za-z0-9_\-]{2,}`, so a prompt in Japanese, Chinese,
Arabic or heavily accented Spanish yields no terms and the hook silently does nothing. Widen
to `\w` with `re.UNICODE` and keep the length floor. Cheap; the stop-list stays English-only,
which is fine — it only ever removes.

**H5 — Same hits re-injected on every prompt of a session. (P1)**
No de-duplication. Twenty prompts about one topic inject the same five items twenty times,
burning context and training the user to ignore the block. The hook payload carries a session
id; keep a small per-session seen-set under `%TEMP%/uoink-recall/<session_id>.json` and skip
any `video_id` surfaced in the last N prompts (N ≈ 10). Same instinct as the Readwise-style
decay already in the engagement layer.

**H6 — No kill switch. (P1)**
A hook you cannot turn off without editing `settings.json` is a hook people uninstall. Honour
`UOINK_RECALL_DISABLED=1` and exit 0 immediately. Also skip when the prompt starts with `/`
(a slash command is not a research question) and when it exceeds ~4,000 characters (a large
paste is not a query about the corpus).

**H7 — Unbounded output block. (P2)**
Text is capped at 160 chars per hit (line 122) but titles, channel names and links are not,
and there are up to 5 hits plus a header. Cap the whole block at ~1,200 characters and drop
hits rather than truncate mid-URL.

**H8 — Silent failure is right; make it observable. (P2)**
Every failure path returns 0 with no output (lines 102, 106, 109, 115, 117) — correct, a hook
must never break the prompt. But there is no way to tell "no matches" from "index missing"
from "sqlite locked." Add `UOINK_RECALL_DEBUG=1` writing one line to **stderr** (never stdout
— stdout is the hook's JSON channel, the same discipline `uoink_mcp.py:46-53` applies to the
stdio server).

**H9 — Read-only posture is correct; document why. (P2)**
The hook opens the live index directly with `?mode=ro` instead of going through the helper's
HTTP API. That is deliberate and worth a comment: it works when the helper is dead (which,
per the 20-hour outage on 2026-09-03, is not rare), and it needs no token. The cost is that it
bypasses the rate limiter and the auth gate — acceptable for a read-only, same-user, local
process. Add `PRAGMA query_only = ON` after connect as a belt-and-braces guarantee.

**H10 — The install path in the docstring is a machine-specific absolute path. (P2)**
Line 9 hardcodes `E:/AI/projects/uoink/checkouts/Yoink-library/scripts/recall_hook.py`. Ship
the installed location, or better, have the helper's "Connect your agent" flow write the hook
entry the way `_handle_agents_connect` (`server.py:12691`) already writes MCP config into
detected desktop clients (`AGENT_CLIENTS`, `server.py:7577`).

**H11 — Clip-layer fallback is right, and the item-level branch should say so.**
`search()` (65) falls back to `yoinks_fts` when `clips_fts` is absent (83-91), which keeps
the hook working on a pre-0024 index. Keep it. Add the level to the header line so a user can
tell clip-grained recall from item-grained recall — right now both print the same sentence.

**H12 — Test it.** `tests/test_recall_hook.py`: a fixture index with two items and known
clips; assert (a) a matching prompt produces the JSON envelope with correct deep links, (b) a
stop-word-only prompt produces nothing and exits 0, (c) a missing index exits 0 silently,
(d) the injected block is fenced and contains no un-fenced clip text, (e) `stdout` is exactly
one JSON object or empty — never both. G3's stdio JSON-cleanliness check is the model.

## 5. The Obsidian / Basic Memory vault mirror

**The machinery already exists.** `memory_layer.py` mirrors `TASTE.md` and `USER.md` to
`<vault>/Uoink/` when `settings.obsidian_vault_path` is set (`_maybe_mirror`, 288-300;
`_atomic_write`, 279-285; the setting is validated and resolved at `server.py:11800-11822`).
Phase 4 extends the same function to the corpus. No new setting, no new dependency, no new
failure mode — `_maybe_mirror` already logs and returns `{ok: false, error}` without failing
the primary write, which is exactly the right contract for a mirror.

### What is mirrored

```
<vault>/Uoink/
  TASTE.md                     (exists)
  USER.md                      (exists, user-owned, never overwritten)
  Library/
    <Channel>/<slug>.md        one file per item: frontmatter + evidence card
  Shelves/
    <Shelf path>.md            definition, cues, member items as links
  Briefs/
    2026-09-04.md              the daily brief
  Library.md                   index: counts, shelves, recent captures
```

One item file, in Basic Memory's dialect (frontmatter + wikilinks, so the graph builds itself):

```markdown
---
title: "How agents actually run in a loop"
permalink: uoink/how-agents-actually-run-in-a-loop
source: https://youtube.com/watch?v=XXXX
channel: Addy Osmani
platform: youtube
captured: 2026-06-12
shelves: ["AI and ML > Agent harnesses > Loop engineering"]
clips: 34
uoink_slug: how-agents-actually-run-in-a-loop
---

# How agents actually run in a loop

[[AI and ML]] · [[Agent harnesses]] · [[Loop engineering]]

**[8:32](https://youtube.com/watch?v=XXXX&t=512s)** — "the loop is the unit of work, not the prompt"
...10 clips...

_Mirrored by uoink. Edits here are not read back; the corpus on disk is canonical._
```

### Rules

1. **One-way, always.** uoink → vault. The vault is never a source. The single exception is
   the one that already exists: `USER.md` is user-owned and the consolidator never overwrites
   it (`memory_layer.py:328-335`). Everything under `Library/`, `Shelves/` and `Briefs/` is
   generated and carries the footer above saying so.
2. **Never the full transcript.** Evidence cards and clips only. A 4-hour podcast transcript
   in an Obsidian vault is a search-index problem for the user's other tools and buys nothing
   the card does not. This is also decision-3-shaped: the mirror is a *view*, the markdown
   corpus on disk is canonical.
3. **When.** Item file on capture (after the index write, on the same best-effort thread that
   already writes sidecars); shelf files and `Library.md` after each `apply_reshelving`;
   the brief once a day. No polling, no watcher, no new timer — every write hangs off an
   event that already exists.
4. **Deletes.** A soft-deleted yoink gets `deleted: true` in frontmatter and its body
   replaced with a tombstone line, rather than the file vanishing — Obsidian users have
   backlinks pointing at it, and a dangling link is more informative than a missing file. Hard
   purge (the 30-day trash retention, `index.py:44`) removes the file.
5. **Collisions.** Filenames are slugs, which are already unique in `yoinks.slug`. Channel
   folder names get the same sanitizer the corpus folders use.
6. **Failure is never fatal.** Inherited from `_maybe_mirror`. A vault on a disconnected
   network drive logs a warning and the capture succeeds.

### Why Basic Memory specifically

Ryan's Hermes setup already treats a Basic Memory vault as universal memory
(THE-LIVING-LIBRARY §6). Basic Memory reads a markdown folder and builds a graph from
frontmatter and wikilinks — which means emitting `[[Loop engineering]]` in the item file is
the entire integration. No API, no plugin, no protocol. It also makes the distribution play
in §9 of the direction doc concrete: *be the Hermes memory provider that holds other people's
videos.*

## 6. The pin, and the dual-era problem

uoink pins **`mcp==1.27.1`** (`requirements.txt:1`, and the same pin in the installer lock
file) and advertises **`2025-11-25`**, accepting four protocol dates
(`server.py:7499-7504`). The **2026-07-28 revision is final** and it is not a superset:

- **Stateless.** No `initialize` handshake, no session.
- **`subscriptions/listen` replaces server push.** Unsolicited notifications are gone.
- **Sampling, roots and logging are deprecated.**

Consequences for this document, in order of how much they cost:

1. **Nothing here depends on push.** Resources are pull. Prompts are user-invoked. Recall
   rides a client-side hook. That is not a coincidence — it is why §2.4 sets
   `subscribe: false`. The 2026-07-28 revision costs uoink *nothing* in capability, only in
   transport code. Any design that reintroduces a subscription is regressing.
2. **The dual-era build is small on HTTP and large on stdio.** The HTTP path is hand-rolled
   JSON-RPC (`server.py:11969-11990`): a 2026-07-28 surface is a new branch, a new entry in
   `MCP_SUPPORTED_PROTOCOL_VERSIONS`, and dropping the `initialize` requirement for clients
   that do not send it. The stdio path is FastMCP's and moves when the SDK moves — so
   **hold the `1.27.1` pin**, serve 2026-07-28 over HTTP first, and revisit stdio when the
   SDK ships support. THE-LIVING-LIBRARY §8 puts "rewrite off FastMCP" last in Phase 4 for
   this reason; agreed, and it may never be necessary.
3. **`server.json` for the MCP Registry is still missing** (audit N18). It is a distribution
   blocker, not a protocol one, and it is cheap. Worth doing in the same PR as the resource
   surface, since a registry entry that advertises resources is a materially better listing
   than one that advertises 23 tools.

## 7. Build order

Ranked by (reach delivered) ÷ (work), which is not the order the phase list implies:

1. **Recall hook hardening (§4).** Days. Works today, in the client Ryan actually uses, with
   zero protocol work. H1 and H2 before anyone else installs it.

   `clip_chars` decision in §2.3 first.
4. **Prompts (§3).** Days, after resources, and after `SKILL.md` is rewritten.
5. **`server.json` + registry listing.** Hours.
6. **2026-07-28 over HTTP.** A week, and only when a client Ryan uses actually wants it.
7. **Off FastMCP.** Not scheduled. Revisit when the SDK does.
