# D-17, re-ratified: the audit and the two closing changes

**Date:** 2026-09-04 · **Author:** Claude (run A) · **Status:** audit + diff-ready plan. Nothing implemented; codex integrates.
**Scope:** every call path in the checkout that sends a user's corpus text to a model from *server* code.
**Base:** worktree `control-room/589b5e45-d1d-claude`, HEAD `61fae99` (Phase 1 clip-index draft applied). Line numbers are from that commit.

---

## 1. The rule, verbatim

From `DECISIONS-2026-09-04.md`, decision 3, adopted by Ryan on 2026-09-04:

> **the server performs no LLM reasoning on the user's behalf except through named, default-off, metered feature flags; all agent cognition happens in the calling client.**
>
> **Entity extraction gets a named default-off flag** like the other two background jobs; the `usage` field gets read.

Three words carry the whole rule and each is a testable property:

| Word | Property | Testable as |
|---|---|---|
| **named** | every automatic model call is attributable to one settings key a user can find and read | the flag string appears in `_default_settings()`, in the `boolean_fields` allow-list of `_handle_settings_post`, and in the `/settings` GET payload |
| **default-off** | a fresh install with a saved API key makes zero model calls until the user opts in | `_default_settings()[flag] is False`, and the worker's spawn gate reads the flag, not the key |
| **metered** | the user can see what the calls cost after the fact, not just an estimate before | the `usage` block of every response is read and accumulated per feature |

"All agent cognition happens in the calling client" is the Phase 2 clause. It is why
`WORK-QUEUE-CONTRACT-2026-09-04.md` gives the server a queue and no inference: the Librarian
is a job uoink *offers*, never a job uoink *runs*.

## 2. Audit: every `_anthropic_messages` caller

`server._anthropic_messages` (`server.py:1292`) is the single outbound egress to a model.
It is called from five places. Nothing else in the checkout POSTs to a model endpoint.

| # | Call site | Feature | Who starts it | Gate today | Flag? | `usage` read? |
|---|---|---|---|---|---|---|
| 1 | `server.py:1349` in `_test_anthropic_key` (1345) | key liveness probe, `max_tokens=4` | **User**, saving a key in Settings | user action | n/a | no |
| 2 | `server.py:2994` in `analyze_comments` (2953) | Comment Intelligence | **Background** thread `_start_comment_intelligence_thread` (3604) on every capture with ≥5 comments | `_anthropic_key_available()` → `comment_intelligence_enabled` | ✅ `comment_intelligence_enabled` | no |
| 2b | same function | Comment Intelligence | **User**, MCP tool `analyze_comments` (`uoink_mcp_tools.py:2183`) | `_saved_key()` — key presence, flag bypassed **by design** | n/a (user-initiated) | no |
| 3 | `server.py:3172` in `analyze_hook_type` (3118) | Hook Type | **Background** thread gated by `_should_start_hook_type` (3408) on every capture | `_anthropic_key_for_feature("hook_type_enabled")` | ✅ `hook_type_enabled` | no |
| 3b | same function | Hook Type | **User**, MCP tool `classify_hook` (`uoink_mcp_tools.py:2212`) | `_saved_key()` — key presence | n/a (user-initiated) | no |
| 4 | `server.py:3708` in `extract_entities` (3668) | Entity extraction | **Background** thread `_start_entity_extraction_thread` (3768), fired from the capture path at `server.py:4584` on **every** yoink | `_saved_anthropic_key()` — **key presence alone** | ❌ **none** | no |
| 5 | `uoink_mcp_tools.py:1254` in `_byo_call_anthropic` | Writing Studio "Path C" BYO generation | **User**, MCP tool call | `_saved_anthropic_key()` (`uoink_mcp_tools.py:1290`) | n/a (user-initiated) | no |

**The user-initiated / background split is already a deliberate, documented contract.**
`server.py:1215-1226`:

> Feature flags gate automatic background work, but MCP tools are user-initiated calls from
> an agent. Those should only require that a valid key exists, not that the background
> feature toggle is enabled.

That reading survives D-17 unchanged: rows 1, 2b, 3b and 5 are the *calling client* asking
uoink to place one call with the user's own key, in the foreground, on a named item. They are
not "the server performing reasoning on the user's behalf." Nothing about them needs to change.

**Rows 2, 3 and 4 are the ones D-17 governs.** Two of the three comply.

### Findings

**F1 — Entity extraction is the open gap (row 4).** `_start_entity_extraction_thread`
(`server.py:3768-3783`) spawns on key presence alone, from the capture path at
`server.py:4584`, for every item indexed. A user who saved a key for Comment Intelligence
five months ago and left both flags off is nonetheless paying for a ~2,500-output-token
Haiku call on every single capture. The sidecar even encodes the asymmetry at
`server.py:4498`: `"pending" if _saved_anthropic_key() else "skipped"` — key presence, where
its two siblings would read a flag. This is the exact clause Ryan re-ratified.
**Verdict: out of compliance with "named" and "default-off".**

**F2 — `usage` is never read anywhere.** `_anthropic_messages` returns the full parsed
response dict (`server.py:1331`), and every caller passes it straight to `_anthropic_text`
(1334), which reads only `content[]`. A grep across `server.py` and `uoink_mcp_tools.py` for
`usage` returns zero hits. Anthropic's `usage` block — `input_tokens`, `output_tokens`,
`cache_creation_input_tokens`, `cache_read_input_tokens` — is parsed and discarded on every
call. **Verdict: out of compliance with "metered" for all five call sites.**

**F3 — the only "metering" that exists is an estimate, and it is stale.**
`_anthropic_pricing_payload()` (`server.py:1157`) multiplies four hardcoded token *guesses*
(`ANTHROPIC_CI_EST_INPUT_TOKENS = 5_000` etc., `server.py:455-458`) by two hardcoded prices
verified **2026-05-12** (`server.py:451-454`, and the `source_checked` field at 1187). It
reports what a call *would* cost under May's list price, never what calls *did* cost. Grok
owns refreshing the constants under run A; this memo owns the fact that a refreshed estimate
is still not a meter.

**F4 — not a violation, worth recording.** `/facets/backfill` (`server.py:9870-9890`)
returns **HTTP 501** with an explanatory `next_steps`. Bulk classification on the server is
*unimplemented*, not forbidden, and the handler's own docstring says the deferred piece is "a
BYO Anthropic worker pool." Under D-17 that pool must never be built server-side. The
replacement is the Phase 2 work queue: the server hands out evidence packets and the client
classifies. Recommend codex replace the `next_steps` string with a pointer to
`list_library_work` once Phase 2 lands, so the 501 stops advertising a path D-17 closes.

**F5 — Phase 1 additions are clean.** `clips.py`, `Index.search_clips`,
`uoink_mcp_tools.search_clips` and `get_evidence_card` contain no model call and no network
import. Gate G3 (codex) asserts this mechanically. The evidence card is the *input* to
client-side cognition, which is exactly the shape D-17 wants.

## 3. Change 1 — the named flag for entity extraction

**Flag name: `entity_extraction_enabled`.** Chosen to match the two existing names exactly
(`comment_intelligence_enabled`, `hook_type_enabled`, plus the same pattern at
`claim_verification_enabled`, `server.py:739`). No new naming convention.

**Default:** `False`.

**Diff-ready plan** (five edits, all in `server.py`, all mirroring an existing sibling line):

| # | File:line | Change |
|---|---|---|
| 1 | `server.py:730` (in `_default_settings`) | add `"entity_extraction_enabled": False,` directly after `"hook_type_enabled": False,` |
| 2 | `server.py:813` (in `_normalize_settings`) | add `clean["entity_extraction_enabled"] = bool(clean.get("entity_extraction_enabled"))` after the `hook_type_enabled` coercion |
| 3 | `server.py:1075` (in the `/settings` GET payload) | add `"entity_extraction_enabled": bool(data.get("entity_extraction_enabled")),` after the `hook_type_enabled` line |
| 4 | `server.py:11699` (`boolean_fields` in `_handle_settings_post`) | add `"entity_extraction_enabled",` after `"hook_type_enabled",` — this is what makes the flag writable and type-checked by the existing loop at 11734 |
| 5 | `server.py:3774` (in `_start_entity_extraction_thread`) | replace `if not _saved_anthropic_key() or not (video_id or "").strip():` with `if not _anthropic_key_for_feature("entity_extraction_enabled") or not (video_id or "").strip():` |

**Do not change** `extract_entities` itself (`server.py:3677`). It keeps
`_saved_anthropic_key()` so a future user-initiated MCP tool (`extract_entities(slug)`) works
the way `analyze_comments` and `classify_hook` already do. The flag belongs on the *spawn*,
which is what makes the work automatic. This is the single most important detail in the plan:
gate the thread, not the function.

**One consequential side edit:** `server.py:4498-4500` writes
`"entity_extraction_status": "pending" if _saved_anthropic_key() else "skipped"` into every
new sidecar. Once edit 5 lands, that string lies — the sidecar says `pending` while the
worker never spawns. Change it to read the same gate:

```python
"entity_extraction_status": (
    "pending" if _anthropic_key_for_feature("entity_extraction_enabled")
    else "skipped"
),
```

**Dashboard/UI:** the Settings panel that renders `comment_intelligence_enabled` and
`hook_type_enabled` needs the third row, with the same "uses your Anthropic key" cost line.
Copy: *"Entity extraction — pull people, tools, products and companies off each transcript
into the library graph. Uses your Anthropic key (~2,500 output tokens per item)."* Whoever
owns the dashboard template adds it; it is not in scope for run A.

**Migration behaviour for existing installs — Ryan's call, flagged, not decided here.**
`_normalize_settings` starts from `_default_settings()` and overlays the saved file, so an
existing `settings.json` with no `entity_extraction_enabled` key resolves to **False**.
Entity extraction therefore *stops* on the next helper restart for every current user who has
a key. That is the correct reading of "default-off" and it is also a silent behaviour removal
on a shipped feature. Two options:

- **(a) Clean default-off.** Ship as specified. Every install starts off; the user turns it
  back on in Settings. Honest, matches D-17 literally, loses entity rows for anyone who does
  not notice.
- **(b) Grandfather once.** In the settings-read path, if the file predates the flag *and* a
  key is present, write `entity_extraction_enabled = True` once and log it. Preserves
  existing behaviour for existing users; new installs are off.

Recommendation: **(a)**, with a one-line release note. This is a personal-corpus tool with one
user in the room, the flag is two clicks, and "default-off means default-off" is the whole
point of re-ratifying the rule. If Ryan disagrees, (b) is four lines in `_read_settings`.

## 4. Change 2 — read `usage`

Anthropic's Messages response carries:

```json
"usage": {"input_tokens": 5123, "output_tokens": 412,
          "cache_creation_input_tokens": 0, "cache_read_input_tokens": 0}
```

`_anthropic_messages` already parses it and hands it back; nobody looks. The fix is one
helper plus one line per call site.

**Step 1 — accumulate, in `server.py` next to `_anthropic_estimated_cost` (1149):**

```python
def _record_anthropic_usage(feature: str, resp: dict) -> None:
    """Accumulate real token usage per feature, per month. Best-effort:
    metering must never fail a call that already succeeded (D-17: model calls
    are 'named, default-off, metered' -- this is the meter)."""
    usage = resp.get("usage") if isinstance(resp, dict) else None
    if not isinstance(usage, dict):
        return
    ...  # read the four int fields, add to the running bucket, swallow errors
```

**Step 2 — where it lands.** Use the existing `memory_layer` KV table (migration 0006,
`key TEXT PRIMARY KEY, value TEXT, updated_at TEXT`) with one row per feature-month:

- key: `usage.anthropic.<feature>.<YYYY-MM>` (e.g. `usage.anthropic.hook_type.2026-09`)
- value: `{"calls": n, "input_tokens": n, "output_tokens": n, "cache_read": n, "cache_create": n, "model": "claude-haiku-4-5-20251001", "est_usd": 0.0}`

Chosen over a new table on purpose: **no migration**. 0025 is Phase 0's `source_type`
backfill, 0026 is the library substrate; a third contested migration number for a counter is
not worth it, and the KV table already exists for exactly this ("last-consolidation
timestamps ... and other persistent metadata", `0006_v2_schema.sql:56-59`). If per-call rows
are wanted later for an audit trail, that is a `library_usage` table in 0027, and the KV
buckets stay as the rollup.

**Step 3 — call sites.** Five one-line additions, each immediately after the
`_anthropic_messages(...)` call and before `_anthropic_text(...)`:

| Call site | Feature label |
|---|---|
| `server.py:2994` `analyze_comments` | `"comment_intelligence"` |
| `server.py:3172` `analyze_hook_type` | `"hook_type"` |
| `server.py:3708` `extract_entities` | `"entity_extraction"` |
| `uoink_mcp_tools.py:1254` `_byo_call_anthropic` | `"writing_path_c"` |
| `server.py:1349` `_test_anthropic_key` | skip — a 4-token probe is noise in the meter |

`_byo_call_anthropic` calls through the bound backend, so it reads
`server._record_anthropic_usage("writing_path_c", resp)`; no new import.

**Step 4 — surface it.** Extend `_anthropic_pricing_payload()` (`server.py:1157`) with an
`actual` block beside the existing `est_per_video`, priced with
`_anthropic_estimated_cost()` against grok's refreshed constants:

```json
"actual": {"month": "2026-09",
           "by_feature": {"hook_type": {"calls": 41, "input_tokens": 48200,
                                        "output_tokens": 3100, "usd": 0.063}},
           "total_usd": 0.19}
```

That single field turns "metered" from an adjective into a number the dashboard can print,
and it is the first real datapoint against grok's G4 cost model.

**Cost of the change:** four small writes to a KV table per capture, on threads that just
spent 1-4 seconds on a network round trip. Immaterial.

## 6. Verdict

| Clause | Before | After the two changes |
|---|---|---|
| named | 2 of 3 background jobs | 3 of 3 |
| default-off | 2 of 3 | 3 of 3 |
| metered | 0 of 5 call sites | 4 of 5 (probe excluded on purpose) |
| all agent cognition in the calling client | true today; the 501 at `server.py:9885` is the only place that advertises otherwise | true, and Phase 2 gives the 501 a real answer |

D-17 is one flag and one field away from being literally true. Both are small. The reason to
land them before Phase 2 rather than after is that the work queue's entire pitch is "uoink
never calls a model" — the claim needs to be true in the code before it is written on the box.
